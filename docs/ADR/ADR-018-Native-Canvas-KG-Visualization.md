# ADR-018：原生 Canvas 知识图谱可视化

- 状态：已采用
- 决策日期：2026-05-18
- 实现核对日期：2026-10-17

## 背景

知识图谱页面需要在 Android 原生界面中展示实体关系，并提供拖拽、缩放、搜索、邻居展开和无障碍访问。图数据规模可能超过适合同时绘制和布局的数量，读取、布局和绘制分别设置边界。

## 决策

图谱页面采用 Jetpack Compose Canvas，数据从 ViewModel 以原生类型传递。页面复用现有 Compose、Material 3 和协程依赖。Canvas 绘制与无障碍列表使用同一份有界子图。

### 数据读取

`GraphSubgraphStore` 从 Room 存活证据中选择最近更新的节点，初始默认最多 300 个节点。实体搜索直接查询数据库，选中结果后按需展开邻居。展开保留已显示节点，并设置节点与边的硬上限；页面显示已显示数量及当前范围总数。全局、文档和概念模式均在读取时应用范围筛选。

### 布局与生命周期

`GraphLayoutEngine` 使用 Barnes-Hut 四叉树近似斥力，结合边弹簧和中心引力，预期每轮复杂度约为 O(V log V + E)。固定随机种子保证相同输入的确定性；重合点通过叶桶与深度上限处理。

`GraphPhysicsSimulator` 在 `Dispatchers.Default` 计算不可变位置快照，再向 Compose 提交一帧。页面离开可见生命周期或布局收敛后暂停模拟；装饰动画使用同一运行状态门控。手势或数据变化可唤醒模拟。

### 绘制与交互

画布预建节点 ID 到位置的索引，每条边通过索引取得两个端点，避免逐边线性查找。视口裁剪采用线段与矩形相交判断，保留两个端点在视口外但穿过屏幕的关系线。首次打开及重置时，根据子图包围盒计算缩放和平移，使图谱适配屏幕并居中。手动平移、缩放和节点拖拽沿用原生手势处理。

## 验证与限制

JVM 测试覆盖子图范围、搜索与展开、固定种子的布局确定性、线段裁剪和视图适配；微基准在 300、2,000、10,000 节点上分别计算一轮，环境、方法和原始耗时记录在 `.agent/tmp-agent-reports/report-kg-cd.md`。

算法复杂度和 JVM 一轮计时不能证明手机帧率、启动耗时、内存或功耗。设备验证需记录型号、Android 版本、数据规模、采样工具及测量区间；没有这些测量，不给出性能数字或稳定性保证。Canvas 仍可能受数据分布、边密度、标签长度、缩放级别和设备能力影响。

## 影响

有界读取限制页面同时持有的图规模，搜索和展开承担大图浏览。后台布局减少主线程计算，索引与正确裁剪降低绘制开销。数据库原图保留完整数据；页面显示的子图及其无障碍列表具有一致边界。
