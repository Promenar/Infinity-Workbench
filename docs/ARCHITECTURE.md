## 核心架构
本项目是一个基于 Kotlin/Jetpack Compose 的原生 AI 助手应用，采用了典型的 MVVM 架构。

### 模块依赖关系
```mermaid
graph TD
    App[com.promenar.nexara] --> UI[ui层: Screens/ViewModels]
    UI --> Domain[domain层: UseCase/Repository接口]
    Domain --> Data[data层: Repository实现/DAO/Entities]
    Data --> DB[Room Database]
    Data --> LLM[LLM/RAG Engine]
    Data --> RAG[RAG管线: Embedding/Rerank/ImageGen]
    RAG --> Embed[EmbeddingClient]
    RAG --> Rerank[RerankClient]
    RAG --> ImageGen[ImageGenClient]
    App --> Utils[utils: NexaraLogger/LocaleHelper]
    App --> Skills[Skill系统: 8个预设+用户自定义+MCP]
    Skills --> ImageSkill[ImageGenerationSkill]
    App --> Coordinator[GenerationCoordinator: 单一生成任务源]
    Coordinator --> Service[GenerationForegroundService: 后台持续生成]
    App --> Secrets[SecretStore: Android Keystore + AES-GCM]
```

### 关键组件

- **隔离脚本运行时**：`ScriptEngine` 定义语言、执行与取消契约，`QuickJsScriptEngine` 在 `ScriptRuntimeService` 的隔离 UID 中运行。`AndroidScriptProcess` 使用有界 Messenger 消息、UID 与随机调用身份连接主进程；`SupervisedScriptRuntime` 串行复用当前会话服务，每次创建全新上下文，超时、取消和资源超限时直接强退并解绑，死亡后重建。
- **Agent 网络访问（AgentNetworkPolicy / AgentHttpRouting / AgentNetworkAccess）**：`AgentNetworkPolicy` 先按 tailnet 路由名、再按系统 DNS 结果把目标分为公网、局域网、本机与 tailnet（含回环即本机，含私网即局域网），并以 `stateFor(tool, target)` 给出七类工具 × 四类目标的总表；`web_fetch`、`media_fetch` 与脚本每跳重定向重新判定。局域网与本机要求 `AgentNetworkSettings` 中的精确主机白名单（沿用 `nexara_settings/script_lan_hosts`，不进备份）；tailnet 由 `AgentHttpRouting` 固定使用 `TailnetRouting.agentProxy()` 返回的本机 CONNECT 代理并保留原主机的 SNI、Host 与证书校验，代理不可用即失败而不回退直连；其它目标禁用系统代理并把 DNS 钉定到已分类地址。系统网络安全配置不允许的明文 http 在白名单判定前以 `CLEARTEXT_BLOCKED` 拒绝；隧道内失败经 `AgentTailnetProxy.failure` 区分证书错误（`TAILNET_TLS_ERROR`）与连接失败（`TAILNET_PROXY_ERROR`，附原因）。`NexaraApplication.agentNetworkAccess` 组合白名单与 Tailscale 状态为 `AgentNetworkSnapshot`，供“Agent 可达范围”面板与设置 → 工具 → 网络访问展示；MCP、SSH、内置命令与 Termux 的行仅描述既有行为。
- **脚本能力代理**：`ScriptToolRunner` 固定会话工作区及可见挂载身份，`ScriptWorkspaceGateway` 在原文件技能/仓库适配层执行读写删，`ScriptFileApprovalBroker` 提供带来源会话的文件风险审批。`ScriptHttpClient` 与 `web_fetch`、`media_fetch` 共用 `AgentNetworkPolicy` 的目标分类（公网 / 局域网 / 本机 / tailnet）、精确白名单、固定 DNS 和逐跳验证。入口读取与能力请求使用共享 4 槽 `ScriptCapabilityDispatcher`，阻塞系统 I/O 不拖住 watchdog；已进入后端的提交沿用原接口的取消与回滚边界。无数据库版本变化，白名单与写入审批配置不进入备份。
- **按范围授权（ToolExecutionPolicy / CommandToolClassification / RuntimeDataMonitor）**：会话 `ExecutionMode` 只有 `WORKSPACE`（默认）与 `FULL_ACCESS` 两档，`ExecutionModeCodec.parseOrWorkspace` 把旧值 `auto` 映射为完全访问、其它值映射为工作区。`ToolExecutionPolicy.requiresApproval` 是唯一审批入口：工作区档对 `CommandToolClassification` 判定的命令工具（内置 shell/Python、Termux、SSH）逐条审批，两档都审批技能目录变更、`schedule_create` 与 SSH 主机配置，文件工具在工作区路径内免审批。挂载只属于会话且可读写，`SessionMountNormalizationCallback` 在每次打开数据库时把旧全局与只读挂载幂等规整（schema 保持 v26）。`RuntimeDataMonitor` 在内置命令前后比较数据库、`shared_prefs`、`no_backup`、`files/agent_skills` 与诊断日志的元数据，变化写入结果的 `runtime_changes`；它只做检测，不构成访问限制。

- **内置 Linux 环境（domain/linux、data/linux，仅侧载 arm64）**: `domain/linux` 定义运行时、软件包、文件与终端四组契约；`data/linux/LinuxModule` 在 `NexaraApplication` 中装配，运行时为 `Unavailable` 时（Play 渠道为 `DISTRIBUTION`，首选 ABI 非 arm64-v8a 为 `UNSUPPORTED_ABI`）各组改用 `UnavailableLinux*` 桩。`ProcessLinuxRuntime` 从 APK 资产安装 Alpine minirootfs（`LinuxRootfsInstaller` 先解到临时目录、核对摘要后发布，保留旧环境直到成功），以 `nativeLibraryDir` 中的 `libnxproot.so`/`libnxproot-loader.so` 启动 proot（满足 W^X），`LinuxLaunchBuilder` 负责绑定 `/workspace`、`/home/session`（会话私有空间）、`/mnt/<别名>` 与 DNS，并按 `ZoneId.systemDefault()` 经纯函数 `LinuxLaunchTimezone` 生成 POSIX `TZ`（双规则年循环转为 `M` 规则，否则退回当前固定偏移；`spec.environment` 可覆盖），`LinuxLaunchGitIgnore` 只做一次性清理：移除旧版本写入 rootfs 默认 Git 全局忽略文件的受管块，保留用户内容，失败不阻止启动；启动不再改写该文件。安装固定基础包 bash、ca-certificates、curl，git 与 Python 3（含 pip）为可选附加包；`LinuxRunModeRecovery` 提供无损修复（只补缺失基础文件与基础包，不升级、不动 `/root` 与配置）、带损失摘要的重置和 `/root` 项目导出，以 `LinuxRecoveryEvent` 流报告进度。软件包由 `LinuxPackageService` 串行调用 `apk` 并记录来源（用户/预设/Agent 会话），镜像源由 `LinuxMirrorService` 测速与切换；文件由 `LinuxFileSystemImpl` 读写 rootfs，并经 `LinuxDocumentsProvider` 暴露给系统文件选择器；交互终端由 `LinuxTerminalSessionsImpl` 以 Termux `TerminalSession`（`libtermux.so`，仅侧载打包）驱动本地 PTY。Agent 侧执行环境由会话运行模式决定（见下条），`domain/tool/LinuxExecRouting` 只提供可用性查询；Linux 会话的审批类别、工具行“Linux”标记与“完整输出”页随之区分；`/root` 可登记为 `linux_home` 工作区（不进备份、重置时清空）。界面位于 `ui/linux`（环境、软件包、镜像、文件、终端、命令完整输出），路由经 `LocalLinuxNavigation` 注入会话页。
- **会话运行模式（domain/model/SessionRunMode、data/session/SessionRunModeService）**: 每个会话持久化 `run_mode`（Room v27 新增可空列，JSON 备份格式 8；旧备份恢复为空），取值 `LINUX` / `BUILTIN`，只在用户手动切换时改变，运行期不降级。`app.sessionRunModes` 提供 `observe`/`check`/`switchMode`/`modeFor`、新会话默认模式与 `startupCheck`；`check` 返回 `Available`、`SelectionRequired`、`EnvironmentUnavailable` 或 `SessionMissing`。工具装配按模式分流：Linux 会话使用 `shell_exec` 与 `LinuxSessionFileSkill`（路径命名空间由 `LinuxSessionPaths` 定义：`/workspace` 为当前主工作区，`/home/session` 绑定 `filesDir/session_workspaces/<sha256(sessionId)>`，真实路径挂载为 `/mnt/<别名>`，SAF 挂载不可见），内置会话使用受限执行工具与 SAF 挂载。终端与后台任务前后对账 `/home/session` 改动；缺少程序（退出码 127）时提示 `apk add` 由 Agent 申请安装。界面：`ui/chat/runmode` 的顶栏模式标识、模式选择面板与进入会话检查点（修复 → 重置或导出，任一步可改用内置），会话列表顶部的 Linux 不可用提示条。
- **启动自检范围隔离（startup/）**: 数据库与备份恢复仍为阻断步骤；工作区 journal、会话删除、回收站、旧根接管、工具台账、向量队列、后台任务、定时任务等步骤失败时由 `StartupIssueManager` 只隔离对应工作区、会话或子系统，隔离只在本进程有效。所有写入口统一经 `StartupWriteBarrier.requireWritable(rootId, sessionId, path, subsystem)`：技能层由 `StartupGuardedSkillRegistry` 对非只读工具检查，仓库层覆盖 `WorkspaceRepository.withRootMutation`（含 relocate）、文件操作、默认落点、画布、媒体、外部挂载，Linux 文件工具、前后台命令、会话终端（解析 guest 绝对符号链接后检查物理目录）与私有空间导出同样接入；Linux 修复/重置只作用于独立 rootfs，不做工作区检查。读取不受影响。`AppDiagnostics` 为正式版保留不剥离的诊断记录（应用私有目录、总大小滚动淘汰），`DiagnosticRedactor` 集中脱敏密钥、令牌、URL 参数、正文与宿主路径；Agent 诊断会话可用 `app_diagnostics` 与逐次审批的 `resolve_startup_issue`。
- **工作区内部文件与默认落点（domain/workspace/WorkspaceInternalPaths、data/workspace/WorkspaceDefaultFileDestination）**: 回收站、命令待执行标记、版本历史、根身份与后台任务日志存于 `noBackupFilesDir/workspace-internal/roots/...`，必须与用户文件同卷的暂存集中到根下唯一隐藏目录 `.nexara/`；创建该目录时写一次内容为 `*` 的 `.gitignore`，之后尊重用户修改。根身份以随机 nonce 加 inode 判定（不含设备号，系统更新改变 `/data` 设备号后身份不变），目录重建后旧引用失效；旧位置内部文件在首次访问或启动时幂等迁移。后台任务日志以 `job-log:<id>` 引用，经 `BackgroundJobController.readLog` 读取末尾。默认落点区分逻辑目标 `SESSION_PRIVATE` / `PRIMARY_WORKSPACE`（主工作区为已登记工作区且没有用户挂载时落主工作区，否则落会话私有空间），路径呈现与反解析由 `WorkspaceFilePathPresenter` 按会话持久模式选择：内置版私有主根用 `/…`、登记主根下的私有文件用虚拟入口 `/session/…`；`LinuxWorkspaceFilePathPresenter` 用 `/home/session/…` 与 `/workspace/…`（私有主根两入口同源），未定模式用内置版。`WorkspaceFileTargetResolver`、画布镜像、媒体保存与系统提示词“默认文件落点”段共用该选择；画布固定首次绑定的工作区，持久元数据不迁移、返回值按当前模式呈现；媒体默认保存途中主根变化即停止。聊天媒体 `resolve` 在 Linux 会话中解析 `/workspace`、`/home/session`、真实 `/mnt/<别名>` 与 rootfs 普通文件（只读、逐段 fd 打开、不跟随链接），不能解析时保持不可用，不回退到其它根。
- **NexaraApplication**: 全局上下文管理与服务初始化（嵌入/重排/图像生成客户端均在此懒加载）；`onCreate()` 自动创建 `WorkSpace` 物理目录；同时持有唯一 Application 级 `ThemePreferenceStore`。
- **ThemePreferenceStore / NexaraTheme**: `ThemePreferenceStore` 是 `theme_mode` 与 `theme_color_source` 的唯一可变事实源，监听备份恢复产生的偏好变化并通过 `StateFlow` 发布；`MainActivity` 按生命周期收集后交给根 `NexaraTheme`，统一解析系统明暗、Nexara 双配色、Android 12+ 动态色及系统栏图标外观。正式 UI 只消费 `MaterialTheme.colorScheme` 与主题内注入的 `NexaraDomainColors`；Markdown、LaTeX、Mermaid、PlantUML、ECharts 与 HTML WebView 从当前主题生成 CSS/图表色板，主题变化会触发内容重建，无静态深色或 Glass 兼容桥。
- **NexaraPageLayout / NexaraSettingsSection / NexaraSearchTopBar**: 管理页面共享 Material 3 骨架。页面根统一持有 system bars 与可选 IME insets；设置区使用透明连续列表和正文对齐分隔线；搜索由调用方持有 query/active 状态，Top App Bar 只负责焦点、IME、清除、返回优先级和 reduced-motion 兼容过渡。
- **AgentHubScreen / NexaraTabHeader**: 三个主标签页（对话、资料、设置）共用 `NexaraTabHeader` 大标题页头（标题、搜索、页面操作），内容按设置页的 `NexaraSettingsSection` 分组面组织。对话页分“置顶 / 最近（5 个）/ 助手”三组：会话行点开对话；助手行在分组内就地展开（同一时间一个，`rememberSaveable` 保存），列出该助手的全部会话与“新建会话”；置顶、编辑、删除通过长按菜单，并以自定义无障碍动作向 TalkBack 暴露等价操作，助手行的展开状态写入 `stateDescription`；新对话从页头“+”选择助手。会话目录由 `SessionListViewModel` 全量加载（置顶在前、按更新时间倒序），新建、置顶、删除失败时对话页以 Snackbar 提示。原单助手会话列表页 `AgentSessionsScreen` 及 `session_list/{agentId}` 路由已移除。
- **NexaraAdaptivePaneHost / NexaraPaneLevel / 会话检视器（ui/common/NexaraAdaptivePane.kt、ui/chat/ChatInspector.kt）**: 二级内容的自适应宿主。窄窗口时二级内容整页覆盖主内容，`coverSuspended` 为 true 时暂时让出；宽窗口（`nexaraInspectorAvailable`：宽 ≥ 600dp 且高 ≥ 480dp）时宿主不覆盖，经 `LocalNexaraInspectorLayout` 通知主内容，由主内容自己的浮动检视器承载同一份层级。主内容始终在同一组合位置，折叠屏开合不重建其状态。`LocalNexaraPanePresentation` 告知内容当前是整页（`Page`）还是检视器（`Inspector`）：检视器内 `NexaraPageLayout` 与 `GitChangesPage` 不留系统栏内边距，根层不画顶栏与返回（`ResourceExplorerPage(onBack = null)`、`GitChangesPage(onExit = null)`），由检视器页签与收起按钮离开。层级用 `NexaraPaneLevel` 按组合顺序叠放，下层保持组合；`NexaraBackScope` 把非顶层及被整页覆盖的主内容的 BackHandler 改挂到不接收系统返回的调度器，只改提供值不改组合结构。会话页的层级状态为 `ui/chat/ChatPages.kt`（`ChatPage`：运行、资源管理器、Git 变更、画布；独立于单一模态层队列，可保存恢复）：`isPage` 的资源管理器与 Git 由 `ChatRoute` 的 `chatPageLevels` 渲染，窄窗口作宿主整页、宽窗口作检视器“文件”“Git”页签内容；运行与画布只是宽窗口页签。宽窗口下层级的根即检视器当前页签，层级为空表示收起。`ChatScreen` 中检视器宽 360dp（加宽为 `nexaraInspectorWidth`，至多 560dp），`nexaraInspectorPlacement` 判定让位（会话剩余 ≥ 480dp，会话 end padding 让出检视器宽 + 24dp）或浮动（底边停在输入区上方，新审批到来时收起以免遮住会话列底部的审批卡）；收起时有内容（`ChatInspectorBadges.hasContent`：运行中、待批准、计划/后台/状态、Git 改动、画布）显示 `ChatInspectorStrip` 边缘条，否则完全隐藏。运行页签复用 `RunDetailContent`，画布页签复用 `CanvasListContent(showHeading = false)`。宽窗口的 `NexaraModalSheet`/`NexaraBottomSheet` 改为居中 `Dialog`（最宽 640dp，`Full` 占窗口高 88%，`rememberNexaraWideWindow` 按 `LocalConfiguration` 判定），没有下滑退场，`NexaraBottomSheet` 不再调用 `sheetState.hide()`。短选择面板可再给 `NexaraModalSheet`/`NexaraBottomSheet` 传 `popover: NexaraPopoverSpec`（`ui/common/NexaraPopover.kt`）：`nexaraSheetPresentation` 判定窄窗口为底部面板、宽窗口且锚点已量到位置时为 `NexaraPopover`，否则为居中对话框。触发控件以 `Modifier.nexaraPopoverAnchor` 记录窗口内边界，面板可在别处渲染仍贴着控件定位；多个控件共用一个面板时由点按的控件 `pointAt` 交出位置。`NexaraAnchorPositionProvider` 按首选侧（`Above`/`Below`）与对齐（`Start`/`End`/`Auto`，`Auto` 朝窗口中部展开）摆放，首选侧放不下换另一侧，两侧都放不下时放在较大一侧；`rememberNexaraPopoverBounds` 以 `safeDrawing`（含输入法）加 16dp 边距为安全范围，高度上限为较大一侧可用空间与屏幕高 70% 的较小值，内容自行滚动。浮层无遮罩、`focusable`，点外部关闭时记录时刻，触发控件点按先 `consumeRecentDismiss` 以实现“再点一次关闭”。会话页的锚点集中在 `ui/chat/ChatPopoverAnchors.kt`（`LocalChatPopoverAnchors`：模型按钮、运行模式、本轮记忆），`ChatRoute` 渲染 `ModelQuickPickPopover`（`ChatOverlay.ModelQuickPick`，窗口变窄时落到会话设置模型页；“更多会话设置”为 `ChatOverlay.SessionParams`）。生成统计浮层 `GenerationStatsCard` 同样使用该定位器。弹出层是挂在调用处窗口上的 `Popup`：面板必须与锚点处于同一窗口的组合中（例如模型编辑器的类型面板放在 `editorContent` 内），放在对话框之外会被对话框盖住、锚点坐标也不在同一窗口。设置页的短单选（主题模式、语言、协议类型、模型类型、tailnet 设备、搜索深度、改写策略）同样传入 `NexaraPopoverSpec`。
- **NexaraMotion / NexaraNavigationHeader / FolderEntriesList**: `ui/theme/Motion.kt` 定义全站动效基准：层级导航用共享 X 轴（`sharedAxisX`、按深度选方向的 `hierarchicalTransition`），同级替换用 `fadeThrough`，局部显隐用 `expandIn`/`shrinkOut`。`NexaraNavigationHeader` 是面板与浏览器内的二级页头（唯一返回按钮、当前标题、路径或说明、页面操作），`FolderBreadcrumbsBar` 在其上提供目录路径，根目录可经 `onExitRoot` 回到外层；`FolderEntriesList` 与 `FileTextPreviewPanel` 统一目录列表和文本预览的分组外观及状态过渡。外部文件夹（`ExternalFoldersPanel`）在一个全高 `NexaraBottomSheet` 内以管理、添加、浏览、回收区四页切换。`NexaraBottomSheet` 在调用方把 `show` 置为 false 时先执行 `sheetState.hide()` - **私有工作区用户文件操作（data/workspace/DefaultPrivateWorkspaceFiles）**: 实现 `domain/workspace/PrivateWorkspaceFiles`，供资源管理器文件页按 UUID 改名、移动、移入回收站。与目录工作区相同经 `SessionExecutionGate.withSessionMutation` 与生成启动串行，忙碌判定共用 `NexaraApplication.isSessionBusyForUserFileOps`（生成中、待审批）。每项直接调用 `WorkspaceRepository` 的 `rename`（以当前名称作 `expectedName` 的 CAS）、`updateParent`、`moveToRecycleBin`，物理移动、Room 提交与工作区 journal 的一致性和崩溃恢复沿用仓库层；同批中上级目录也被选中的条目不单独操作，结果继承上级（上级失败则同计失败）；同一条目重叠的改名请求只接纳首个，服务须为单例。改名提交时已清空 `vectorizedAt`/`kgExtractedAt`，提交后为 `affectedTargets` 向 `PendingDocumentIndexCoordinator` 发布 `FileIndexEvent.Changed`，发布失败由协调器保留重试，进程在提交后退出则由向量化队列启动时扫描未向量化文件补排；仅换目录时向量元数据（`fileUuid` 与文件名）不变，不重建。回收由 `WorkspaceLifecycleTransaction.recycle` 在同一事务内清除向量与派生数据。改名与移动的目标占用（数据库条目或未纳管的物理文件）统一为 `WorkspaceLifecycleException(TARGET_COLLISION)`，映射为 `NAME_EXISTS`。界面状态 `PrivateFileOpsState`（选择以 UUID 为键并保留条目快照，剪贴板 `PrivateFileClipboard` 记 UUID 与物化路径，粘贴目标沿用 `DirectoryClipboard.canPasteInto`）由 `ResourceExplorerViewModel` 持有，切换会话即重置并丢弃旧会话的迟到结果；`FilesPanel` 传入 `onToggleSelection` 时改为长按多选、不弹条目菜单，`WorkspaceFolderBrowser` 底部复用 `DirectorySelectionBar`（不含复制）、`DirectoryPasteBar`、`WorkspaceNameDialog` 与 `DirectoryDeleteDialog`。
- **Repository 层**: 通过领域接口隔离 Room 持久化、工作区文件操作与业务状态；测试数量和实现范围不等同于代码覆盖率，覆盖率目标按独立测量报告验收。
- **ContextBuilder**: 负责多源上下文（RAG/Web/KG/History）的异步调度、打分与 Prompt 合成，支持实时观测回调。查询只规范空白，保留技术符号、否定与实体信息；取消异常向父协程传播，阻止后续检索、模型及工具执行。所有子源接入 NexaraLogger 错误追踪。
- **MemoryManager**: 核心 RAG 检索引擎，集成 Embedding/Rerank/Hybrid Search 三阶段检索管线。embedQuery/search/rerank 全路径接入日志。对话记录按时间线注入（`MemoryTimeline`）：时间取 `start_message_id`（缺失时 `end_message_id`）对应消息的 `created_at`，经 `MessageDao.getCreatedAt` 批量读取，查不到时回退向量行 `created_at`；时间只写在注入正文的记录前缀中，不进入向量正文与 FTS。对话候选（memory 与 summary）按相似度加候选内名次线性的新近度分（`RECENCY_WEIGHT` 0.05）排序；`parseRecallTimeRange` 在问题含回顾意味且含时间表达时给出左闭右开时段，该时段内的对话记录不设阈值检索并优先入选。memory 取 `memoryLimit` 条、summary（事件）另取至多 3 条。state 行经 `latestStates` 每键取最新值并丢弃撤销值，不超过 24 条时全部注入，超过时一半按相似度、其余按更新时间选取；当前状态在无相似记录时也注入，引用类型为 `state`，不显示相似度。注入顺序为：当前时间与先后规则、当前状态、按时间先后的事件与记忆、按相关度的文档；`RagReference.occurredAt` 记录记录时间。
- **模型请求路由（data/remote/ProviderRequestRouter.kt、ModelRequestRoute.kt）**: 应用内模型以稳定 ID `providerId::remoteModelId` 选择与存储；任何发往上游的请求都先经 `ProviderRequestRouter.resolve` 得到 `ResolvedProviderModel`，地址、凭据与 `remoteModelId` 只取自这一次解析结果，不对稳定 ID 做字符串裁剪。聊天、摘要、标题、KG、子代理直接使用解析结果；生图（`ImageGenerationSkill`）、Embedding、Rerank 与查询改写经 `requireModelRoute` 解析，图像、Embedding、Rerank 再经 `requireOpenAiModelRoute` 限定 OpenAI 兼容协议（Embedding 另允许本地模型）。解析失败抛 `ModelRequestRouteException`，调用方明确报错且不回退主提供商。`NexaraApplication.embeddingClient` 是按调用读取当前预设的委托客户端，预设优先于历史手动配置。
- **SessionStateMemory（事件与状态）**: 开关 `RagConfiguration.memoryStateExtractionEnabled`（默认关闭）经 `KgAdvancedSettings` 保存为 `memory_state_extraction` 并纳入备份白名单。生成成功且对话记忆开启、可嵌入时，`SessionStateScheduler` 排入 `session_state` 任务（id 为 `session-state-<助手消息id>`），由 `VectorizationQueue` 持久化、准入、删除屏障与中断恢复管理，失败任务按队列重试后清理不长期保留。处理器经 `KgRequestClient.extract`（独立响应解析器，用量计入同一统计）调用摘要预设模型或主模型，输入附同一助手最新的至多 40 条当前状态以复用对象与属性写法；输出 `{"event", "states"}`，最多 8 条状态，`value` 为 null 表示撤销。结果写入 `vectors`：事件为 `{"type":"summary","kind":"event"}`，状态 metadata 依次为 `type/key/subject/attribute/value`（`key` 为 NFKC、去空白、小写后以 U+001F 连接），`created_at` 等于本轮用户消息时间，同轮重写在事务内先删后写；写入前复核任务快照与两条消息的正文、父链与时间，抽取期间被编辑或移除的轮次不写回。summary/state 行与 memory 行同样跟随轮次消息可见、撤销与孤儿回收，但 `getMemoryBy*` 与 `turnChunkCount` 只计 memory 行；编辑用户消息与 `removeTurn` 删除该轮事件与状态，编辑助手消息与 `rewriteTurn` 重新排入抽取。
- **VectorizationQueue / DocumentIndexService / PendingDocumentIndexCoordinator**: 文档/记忆持久队列、候选索引事务服务与应用级补偿目标协调器。文件内容先构建隔离向量/KG 候选，事务内复核 hash+epoch 后原子切换；旧 worker 使用目标 CAS，删除通过 cancel-and-join/fence 屏障线性化。Queue 尚未接收的已提交目标可跨页面重试，并由冷启动 missing-scan 按当前文件版本与 KG 配置恢复。启动恢复只清理缺少身份或已确认文件不存在的旧版 `document` 孤儿任务，现代 `document_reference` 目标继续遵守 hash+epoch 契约。
- **WorkspaceRepository / WorkspaceDeletionTransaction**: Session root 作用域文件仓储。创建使用持续身份证明与不可覆盖的原子发布；回滚先隔离再核验归属，仅清理已证明属于该操作的节点。私有操作目录由根锁独占。永久删除把派生索引与文件记录纳入同一 Room 事务，并用稳定 tombstone 恢复物理删除的进程死亡窗口。
- **持久文件身份（data/repository/PersistentFileIdentity）**: 凡写入磁盘、Room、xattr、journal 或跨重启再比较的文件身份统一为 `nx1:<nonce>|sha256(ino=<n>)`，磁盘根标记为 `nx1:<nonce>` 换行 `ino=<n>`，生成、解析与 inode 绑定校验集中在此。工作区根 nonce 存于 `user.nexara_root_identity`，其它节点存于独立的 `user.nexara_persistent_identity`（不覆盖创建归属令牌），写入用 `XATTR_CREATE` 并在返回前 fsync；不支持属性或无法同步时失败关闭。私有索引键与私有区域键为 `sha256(nx1身份)`。工作区根、创建归属 manifest、后台基线、备份与双库恢复 journal、Skill 恢复、Linux rootfs 与包来源均使用该身份；Linux 目录工作区来源只取 inode，不向用户目录写属性。操作期间的路径/FD 防替换仍比较含设备号的完整 fileKey。工作区根认领是唯一迁移的旧格式：`nonce|sha256(完整fileKey)` 由 `WorkspaceFileMutationRecoveryCoordinator.adoptLegacyRootIdentityOrThrow` 在根恢复、放弃与会话删除 journal 恢复前处理，经 `WorkspaceFileOps.adoptLegacyRootIdentity` 核验后（无根标记文件时要求目录属性 nonce 与当前完整 fileKey 按旧算法逐字吻合；有旧格式根标记 `<uuid>` 换行 `(dev=…,ino=…)` 时要求标记 nonce 与认领一致、标记 inode 等于当前 inode、认领摘要等于标记中 fileKey 原文的摘要，属性 nonce 若存在也须一致），持根锁先 `adoptLegacyRootPrivateData` 把私有区改到新键下（新旧并存则拒绝合并），再在同一事务中改写根认领与 `expectedSha256` 等于旧认领的未完成 journal；核验失败时零写入并以 `LEGACY_ROOT_UNVERIFIED` 隔离该根。旧格式根标记要保留到私有区迁移与数据库事务完成，之后才由 `ensureRoot` 改写为 nx1 标记（无私有索引时经临时文件原子替换）或删除；没有数据库认领的目录（如会话工作区父目录）只要求旧标记 inode 与当前一致。`ChatViewModel` 新建、补建与冷加载会话时捕获工作区身份异常并按会话呈现错误，不放宽文件端口的检查。其它旧格式不迁移，恢复快照 manifest 为格式 3。外部 FUSE 或可移除卷重新挂载改变 inode 时旧身份被拒绝，需重新登记。
- **DualDatabaseRecoveryBootstrap / RecoverySnapshotStore / AndroidDualDatabaseRecoveryExecutor**: 正常 Room 和业务写入启动前识别公开 v17+v2 及内部 v17+v5 双库，用户选择后保存一致快照，在独立 working 副本迁移与映射。旧侧业务 ID 进入稳定命名空间；文件发布到受信目录的新根并绑定新物理身份，已确认归档只从认证副本读取。可信 Android 系统路径别名仅在应用根身份一致时规范化，用户子路径继续使用目录 FD 与 NOFOLLOW。journal 覆盖归档、文件发布、数据库切换及中断重试；源数据保留，终态后不回放新业务写入。
- **RagWorkspaceProvisioner / LegacyAttachmentCodec**: 恢复的全局知识库以受控系统 Session 独立浏览；多来源切换取消旧观察和搜索，默认分享保持固定知识库入口。历史附件原 payload 保留，打开时才有界读取并发布 FileProvider 只读 URI；损坏或超预算记录显示原因，内容哈希缓存最多 16 项/64 MiB。恢复中的旧索引任务保持人工重试状态，不自动重放。
- **DocEditorContentAccess / DocEditorViewModel**: 文档内容访问使用 `Editable / PerformanceProtected / MetadataOnly` 单一事实。文件大小严格超过 1 MiB 时不读取全文；已读取内容严格超过 32K 个 UTF-16 代码单元、2,000 行或单行 16K 个 UTF-16 代码单元时，仅向 Markdown 提供最多 16K 个 UTF-16 代码单元的快照，不构建全文 `BasicTextField`。完整 `content/persistedContent` 仍是复制、dirty、expected-hash CAS 保存与冲突处理的唯一数据源，预览 snippet 不得进入持久化路径。 编辑/预览/分屏使用同一 Row 内的稳定面板调用位置，模式间共同面板保留选区与内部状态；隐藏面板卸载，避免隐藏焦点树。
- **SharedFileImporter / DurableShareInbox**: SAF 与系统分享共用的逐项导入管线；UTF-8 前缀允许有限续读，全文保持严格编码验证。HTML 走有界离线正文提取，不加载脚本或远程资源；DOCX 按实际展开字节及条目数预检，PDF 输出和文本分块遵守 Unicode 与字节预算。逐项回滚、批次容量和索引回执保持一致。收件箱去重按投递来源区分：已消费指纹只拦截系统重放的同一 Intent（保存状态重建、最近任务重启），用户新的分享只与待处理请求去重；启动恢复以已消费 requestId 识别 ack 残留目录。
- **GenerationCoordinator / ChatGenerationRunner**: 应用级唯一生成任务源。初版全局只允许一个活动任务；统一处理 Provider 路由、RAG/工具循环、流式增量持久化、取消与结构化错误终态。成功、失败与取消路径必须先把终态发布到 `GenerationPresentationStore`，再结束协调器活动状态，避免 UI 因事件顺序停留在生成中。
- **MessageDocumentAttachment / PreparedPromptBudgetGate / BranchSessionUseCase**: 输入栏 TXT/Markdown 以版本化消息快照进入完整用户上下文，与知识库检索分离；最终路由 Prompt 在 Provider 网络前按稳定模型覆盖和远端目录容量执行 fail-closed 门禁：输出预留取显式 maxTokens，未设置时为模型最大输出与 32768 的较小值；仅携带完整文档的请求按 UTF-8 字节保守计量，其余与自动压缩同用 `ApproximateTokenEstimator`，两者共用 `PromptWindow.inputBudgetTokens`（窗口减输出预留与 2% 安全余量）。重试只在新回复成功后替换旧回复；导出可回传，稳定消息分支重映射历史并清空运行态与工作区身份。
- **GenerationForegroundService**: 观察 Coordinator 的同一任务状态，通过 `dataSync` 前台服务在切后台、锁屏、旋转或 Activity 重建后继续当前生成；通知可返回准确会话或停止任务。设备重启续传与多会话并行不在范围内；无人值守的轮次经下述系统触发调度器进入同一 Coordinator。
- **后台任务（data/jobs、background/jobs）**: `BackgroundJobManager` 是应用级控制器（实现 `BackgroundJobController`），记录以 JSON 存于 `noBackupFilesDir/background-jobs/records.json`（Mutex、临时文件、fsync、原子 move），不进入备份；内置进程以进程组运行，恢复身份用开机计数与 `/proc/<pid>/stat` 启动时钟核验，日志 20 MiB 单轮转，实时输出键 `job:<id>` 共用 `toolLiveOutputStore`。私有根任务由 `BackgroundWorkspace` 在根锁下复制副本并记基线哈希，结束后对基线 B、真实根 C、副本 S 三方合入，冲突写入 `jobs/<id>-conflicts/`，发布有持久恢复日志；Termux 任务用 `setsid nohup` worker 与看门狗，取消先落墓碑。侧载以执行登记表和前台服务保活，Play 只在可见期间持唤醒锁。`BackgroundJobCompletion` 按 `on_exit` 通知（`background_jobs` 通道，会话令牌深链）或向系统触发调度器提交 `JOB_EXIT` 请求。会话删除先停止任务，`cleanupSessionRuntimeData` 最终清理。Linux 会话的命令经 `LinuxExecPtyBridge`（libtermux 包内 JNI）建立伪终端，`LinuxExecPtyProcess` 适配为 `Process`（非阻塞读写、进程组信号），`LinuxExecTerminalText` 有界清理 ANSI 与回车覆盖；`BuiltinCommandRunner` 在同一计时循环中到达让出阈值时先扩大时限再唤醒前台等待者，`BackgroundJobManager.runLinuxForeground` 接管同一进程（记录字段 `directWorkspace` 与 `commandResult`，兼容旧记录），结束后由原前台路径对账并写入完整结果；`job_input` 经 `BuiltinCommandControl` 写入 PTY，审批目标绑定任务号与输入正文、不可记住。执行类工具参数由 `ExecToolArguments` 做无歧义的布尔/数字字符串转换（结果带 `argument_notes`），校验错误给出字段路径、期望与实际类型。
- **系统触发与定时任务（domain/trigger、data/trigger、data/schedule、background/schedule）**: `DefaultSystemTurnDispatcher` 在应用作用域等待备份启动门禁就绪后全局串行处理 `SystemTurnRequest`：同源新请求替换未开始的旧请求，其它生成、待处理确认或任何会话存在待审批时轮询排队（`SessionDao.hasPendingApproval` 轻量查询），30 分钟未开始则以 `BUSY_TIMEOUT` 跳过；已开始的轮次只有系统执行窗口被撤回时才经 `stopSource` 定向中断。`ApplicationSystemTurnRuntime` 与页面共用 `ChatStore` 载入锁和轮次准入，写入 `name=system_trigger` 的用户消息（首行 `<system_trigger …/>` 标签，`SystemTriggerMessage` 编解码，界面渲染为居中触发行），以 `GenerationInteractionMode.HEADLESS` 发起生成：工具审批写入会话 `approvalRequest`，重复调用/无限自动确认持久化到 `noBackupFilesDir`，通知点击后由既有审批接续路径在原用户轮次上恢复。`DefaultScheduledTaskController` 持有 Room v26 `scheduled_tasks`（identity hash 校验同步扩展到恢复探针），每次领取先持久化 `run_count` 与执行令牌，完成/中断只更新匹配令牌，启动时残留领取记 FAILED 不重放；`CronExpression` 为无依赖五段解析。`ForegroundScheduleTicker` 在 `ProcessLifecycleOwner` 处于 STARTED 时按最近计划时刻在应用作用域准点调用 `fire`（每次到期只尝试一次，触发独立于任务列表收集以免领取改写行时取消生成），系统排期保留为后台兜底，两路重复回调由领取令牌去重。`next_fire_at` 只表达前台节奏（固定间隔最短 1 分钟）；后台登记时刻由纯函数 `ScheduleCalculation.backgroundFireAt` 取 `max(next_fire_at, (last_fired_at ?: created_at) + 下限)`（精确 5、非精确 15 分钟，单次不受限），平台回调以 `background = true` 进入 `fire` 并在领取前检查该时刻，防止周期 Job 在窗口内提前消费前台计划；补发迟到按领取前任务行的后台时刻计算（claim 会改写 `last_fired_at`），权限变化只更新 `exactEffective` 并重新登记。固定间隔生成越过计划时刻时下一次为结束时刻加完整间隔。`once.in_minutes` 在工具执行时以设备时钟换算为本地时间存入既有 `Once` 字段，无表结构变化；夏令时回拨重复时段内的倒计时按较早偏移解析，属已知局限。`AndroidScheduleBackend` 用 JobScheduler（固定间隔首轮单次 Job、之后周期 Job）与侧载精确闹钟（`ScheduledTaskAlarmReceiver` → dataSync 前台服务），开机/更新/时区与精确权限变化广播只重排。`SystemTriggerNotifications` 使用 `agent_trigger` 通道，`AndroidSessionOpenIntentFactory` 签发一次性 24 小时会话令牌（应用私有偏好，不备份），`AppIntentRouter.ACTION_OPEN_SESSION` 校验后导航。分发清单检查确保 Play 不含精确闹钟权限。
- **SecretStore / SecretCatalog**: Android Keystore 生成不可导出的 AES-GCM 主密钥；普通偏好只保存密文、IV 与格式版本。Provider、Vertex、搜索、Embedding 和 WebDAV 凭据由稳定 SecretId 管理，UI 只持有存在性和短生命周期 reveal 内容。
- **BackupRepository / BackupPackageCodec**: 核心数据采用清单、逐项 SHA-256 和事务恢复；可在不导出密钥时独立加密整个备份，导出密钥则强制启用密码与 PBKDF2-HMAC-SHA256/AES-256-GCM。快照在配置 revision 前后复核，持续变化时失败关闭；个人及 Agent 头像路径属于设备本地数据，跨设备备份会剥离。备份根的系统别名先按父目录身份唯一匹配，再重拼到既有受信 base，保留旧 journal 的 baseIndex/fileKey 合同。恢复先验证再写入，错误密码、损坏包和越界内容不得产生部分写入。
- **ToolExecutionLedgerRepository / McpClient / SessionToolResolver**: 工具执行以 runtime id、规范化参数摘要和定义摘要组成稳定身份，注册、审批、认领、取消及恢复均以精确身份 CAS；取消后只允许一个 `CANCELLED` 终态。MCP 仅支持 HTTPS Streamable HTTP，增量 SSE 只接受首个精确响应 ID，合法 notification 可忽略，错误版本、错 ID、畸形/截断事件及行、事件、总量上限全部失败关闭。
- **ModelMetadataResolver / ModelCatalogRuntime**: 模型元数据唯一领域入口。运行时只读取仓库内固定的 models.dev 离线快照和 Nexara 精确修正，再按字段叠加 Provider 元数据与用户覆盖；精确名称、工作负载、三态能力、token 限制和来源可追踪，家族规则不得覆盖精确字段。
- **ModelSelectionUiModel / ModelSelectionListItem**: 模型选择 UI 的统一投影与渲染契约。`ModelInfo` 先把 Provider 数据和 `userEditedFields` 转换为分层 override，再调用 `ModelMetadataResolver.resolve(...)`；所有选择入口消费同一冻结投影与连续 Material 3 `ListItem`。`CHAT_ENDPOINT` 不混入一般能力集合，显式不兼容优先于生成式工作负载，未知能力不得被 UI 制造为支持。
- **MicroGraphExtractor/GraphExtractor**: 全量与 JIT 共用模型稳定 ID 路由与图校验；全量/手动候选通过 DocumentIndexService 的 hash、epoch、任务标识与删除准入事务提交。JIT 在容量 8 的串行后台队列中登记缓存及会话证据，提交前核验文档版本；缓存身份包含查询、完整片段内容、模型、提示词摘要及文本预算。
- **GraphStore / Room v23**: `kg_nodes` 以全局 `(normalized_name, type)` 唯一，名称执行 Unicode NFKC、首尾/连续空白归一和与设备语言无关的大小写折叠；类型同样归一。`kg_edges` 以有向 `(source_id, target_id, normalized_relation)` 唯一，端点外键为 RESTRICT。`kg_evidence` 单独记录实体或关系的 document/session/jit/legacy 来源、文档/会话、内容 hash、抽取任务、时间及关系的来源置信度；读取权重按当前文档/会话范围的存活证据取最大值，避免已失效来源污染排序。会话图谱抽取（`vectorization_tasks` 类型 `session_graph`）写入的 `session` 证据带 `message_id`（该轮最后一条助手消息），可见条件要求该消息存在；每轮状态由任务行（排队、进行中、失败、未完成）与按消息统计的证据推出，不另存列。关系写入同步证明端点，唯一约束与事务确保并发幂等。
- **知识图谱页（KnowledgeGraphScreen / KgSessionGraphStore / InteractiveGraphCanvas）**: 三个视角对应三种查询范围（`KgScope` 全局、文档、会话），scope key 判定迟到结果与缓存归属；`GraphSubgraphRequest` 与 `GraphEntitySearchRequest` 的 `docId` 与 `sessionId` 互斥。会话范围只取存活的 `source_type = 'session'` 证据，边权重按该会话证据取最大值。`KgSessionGraphStore` 在 IO 调度器与 Room 事务内提供会话选项（最多 1000 个，按最近证据时间降序）、轮次（最早 400 轮、实体出现记录上限 20000，越界整轮舍弃以保证每轮实体完整；轮号为会话内时间不晚于该助手消息的用户消息数，首次出现用窗口排序判定）与实体来源（文档与会话轮次各默认 20、上限 100）。画布在布局坐标中绘制连线与节点，节点半径按 dp 计、只随缩放平方根在 0.75–1.4 倍间变化；文字在屏幕坐标绘制。高亮由 `KgHighlightResolver` 统一判定（选中实体及一跳邻居、选中轮次、类型筛选），标签按细节层级显示。布局展开期间未经用户操作时逐帧适配视野，画布尺寸变化只在用户未调整视角时重新适配。
- **KG 来源生命周期**: 文档/会话删除在事务内只移除对应证据，回收该来源原先涉及且已无证据的关系与实体。JIT 多文档联合推断缺少逐关系的独立来源证明，任一输入失效时保守撤销整次推断；其它独立来源保持。`kg_jit_cache_sources` 登记缓存的文档依赖，包括空图；删除文档同步失效缓存。读取通过存活证据筛选，全局图共享实体，文档/会话视图按证据过滤；源/目标索引和结构化种子查询支持后续 1–2 跳读取。
- **对话记忆生命周期（ConversationMemoryLifecycle）**: 对话记忆每轮一组向量，`start_message_id`/`end_message_id` 为该轮用户消息与助手消息；`VectorDao` 的公共可见条件要求两者都存在，删除、丢弃、回退、清空立即生效，撤销以原 id 恢复消息即恢复记忆。删除时以 `stale`/`updated_at` 标记失去所属消息的记忆，应用启动时物理删除超过 24 小时撤销窗口的部分。用过本会话对话记忆的 JIT 任务，其全部即时证据随删除或编辑撤销并回收孤立节点与边，同时清空 JIT 缓存。编辑用户消息删除该轮记忆，编辑助手正文按新正文重写。
- **记忆写入状态（TurnMemoryState）**: 每轮写入对话记忆的状态（writing / stored / failed / removed）以 JSON 存放在该轮最后一条助手消息的 `vectorization_status` 列，只经 `MessageDao.updateTurnMemoryState` / `compareAndSetTurnMemoryState` 定向改写，摘要归档的纯文本状态（`updateArchiveVectorizationStatus`）不覆盖 JSON；`updatePartial` 的整行读改写在 `MessageDao.updateWith` 事务内完成。早期纯文本值按无状态处理。写入统一经 `MessageManager.writeTurnMemory`：先记 writing，最终状态仅在仍为本次 writing 时落盘，取消时按实际片段恢复；`reconcileTurnMemory`（打开会话、撤销删除后）把没有写入在进行的 writing 按 `ConversationMemoryLifecycle.turnChunkCount` 改为 stored 或 failed。`removeTurn`/`rewriteTurn` 支撑“本轮记忆”面板的移除与重新记入；`onMessageEdited` 返回受影响各轮的新状态（编辑用户消息为 removed，助手重写失败为 failed）。检索轨迹 `RagRetrievalTrace` 记录实际执行的档位、对话记忆覆盖的会话与助手数（`RetrievalScopeResolver.stats`）以及 JIT 次数与模型。
- **检索范围（RetrievalScopeResolver）**: 会话 `RagOptions` 以 `memoryScope`/`graphScope`/`documentScope` 表达三类资源的档位，旧字段 `isGlobal` 只在新字段缺省时参与解析；`ContextBuilder` 按助手 `AgentMemoryPolicy`（保存在 `retrieval_config` 中，继承全局参数时也保留）收紧到上限。`RetrievalScopeResolver` 把档位解析为会话集合（按 `sessions.agent_id` 判定，“全部助手”排除未共享的私密助手）与文档范围（工作区根 + 显式文档与展开的文件夹，或全部已索引文档）；`VectorDao` 的范围查询、`KeywordSearcher.searchScoped` 与 `GraphRetrievalStore` 的 `visible_sessions`/`visible_docs` 都从同一解析结果取范围。
- **长期记忆（data/memory）**: 用户级、与会话和消息解耦的记忆，Room v28 表 `long_term_memories`（`kind` 为 user/feedback/project/reference，标题 ≤80、正文 ≤2000 字符，来源助手/会话/消息只记录不建外键，`updated_at` 索引）。`RoomLongTermMemoryRepository` 在 IO 上以事务完成同标题去重（Kotlin Unicode 忽略大小写）、200 条上限与凭据模式拒绝（`LongTermMemoryValidation`），`restore` 按原 id 与时间戳写回供撤销。`RoomLongTermMemoryAccess` 每次读取实时会话与助手：会话关闭工具、私密助手（`AgentMemoryPolicy.shareWithOtherAgents == false`）或全局开关 `long_term_memory_enabled` 关闭时既不注入也不广告工具；`DefaultSessionToolResolver` 经同步桥 `isEnabledForToolAdvertisement` 判定，调用方都在生成或 IO 线程。工具 `memory_save`/`memory_forget`/`memory_read`（`ui/chat/manager/skills/LongTermMemorySkills.kt`）不审批，结果 JSON 带撤销所需的写入内容、`previous` 与被删记录的来源和时间。`ContextBuilder` 每个续轮重新读取，在 `DATA_BOUNDARY` 资料区以 `### Long-term memory` 注入（`LongTermMemoryContext`，正文预算 6000 字符，超出后只列标题）。界面：`ui/chat/MemoryToolPresentation.kt` 把成功的写入/删除解析为“已记住”步骤行，`memoryUndoState` 仅在记忆仍是该次改动结果时提供撤销，`LocalMemoryChangeHost` 由 `ChatRoute` 以 `observeAll` 提供，完成态收起时 `TurnProcessSummary.memoryChanges` 让这些行留在摘要下方；管理页 `ui/memory/LongTermMemoryScreen.kt`（路由 `long_term_memory`）。备份格式 v9 含该表，兼容 v1–8。
- **子代理（agent_task / SubagentLauncher / SubagentRunner）**: 内置工具 `agent_task` 在父工具协程内并行运行 1–3 个子代理，父轮取消即一并取消；子代理复用父会话模型的精确路由，每轮与每次调用前重读父会话，工具集排除 `agent_task`、`view_media` 与会话状态级工具（只读档位只保留只读工具），最多 12 步，单个子代理合计不超过 400k token，任务 token 上限按子代理数分摊，不执行自动检索；本地模型推理逐个占用。审批判定与父会话一致，需要授权时由 `SubagentApprovalBroker` 原地挂起；当前路由为该会话聊天页（`NavDestinations.CHAT_HERO`）时，`ChatRoute` 把本会话的请求交给 `ChatScreenState.subagentApprovals`，在会话流底部以 `SubagentApprovalGroup` 呈现，其余情况在应用全局弹窗（`SubagentApprovalDialog` 以 `inlineSessionId` 跳过前者；无专门预览的工具展示完整参数，批准后重新解析目标，不一致不执行），后台时发高优先级通知，10 分钟未处理以失败交回；“允许并记住”写入父会话白名单。`SubagentRunStore` 运行中只存内存，结束后写入 `noBackupFilesDir/subagents/<sha256(会话)>/<sha256(工具步骤)>.json`，进程重启后的运行中记录显示为已中断，父会话删除时随 `cleanupSessionRuntimeData` 删除；用量经账本在工具结束（含取消）后于不可取消区并入父轮助手消息的附加用量。
- **推理强度与参数方案（ModelParameterProfile / ModelAdaptedRequest / ParameterSchemeRepository）**: `resolveModelParameterProfile(协议, 远端模型 id, 接口地址)` 按模型族表给出推理控件形态（写法、档位、能否关闭、文档默认档位）及每个采样参数的 `ParamAvailability`：协议请求体没有的字段不显示不发送；文档列出的限制只在接口主机属于该厂商官方域名（含子域名；空地址取协议默认地址，Gemini/Vertex 协议视为官方）时生效——官方接口收进“不适用”分组或标“思考时不生效”并剔除，第三方中转、自建与本地接口只标“可能被忽略”并照常发送用户设置的值。推理写法只在协议能表达时提供，否则隐藏控件但采样限制照常生效。各协议 `buildRequestBody` 先经 `PromptRequest.adaptedTo`（传入协议的接口地址）剔除应剔除的采样参数并把保存的档位换成模型可发送的最近一档，再按写法写入推理字段，因此所有调用方（含子代理、摘要）统一受约束。参数解析顺序为会话 → 助手 → 模型默认（不发送）：会话 `InferenceParams.parameterSchemeId` 非空（某个方案或 `model-default`）时采样参数完全由会话决定，推理强度仍逐项回退，会话里的 `default` 推理取值表示显式模型默认。参数方案按稳定模型 id 存于 `parameter_schemes`（`SamplingValues` JSON），会话与助手编辑页共用 `ui/common/params` 编辑器：参数行点按原位展开统一的加减、直接输入与快捷值编辑区（停顿 400ms 后写入），标题旁标签标出来源与可用性；“已修改”只比较当前可编辑的参数。
- **触感反馈（NexaraHaptics / ChatStatusHapticTracker）**: 所有振动经 `ui/common/NexaraHaptics` 的事件类型（选择、步进、开关、确认、拒绝，以及状态类的等待审批、完成、失败）映射到 `View.performHapticFeedback` 常量，新常量不可用的系统回退到语义最接近的一档；不申请振动权限，系统关闭触摸振动时由系统忽略。`NexaraTheme` 按外观偏好（`haptic_enabled`、`haptic_status_enabled`，均在 `nexara_settings`，随备份迁移）提供 `LocalNexaraHaptics`，并在关闭触感时把组件内置的 `LocalHapticFeedback`（长按菜单、文本选择）替换为静默实现。开关、步进器、有刻度滑块、分段与标签切换、单选类选择（`NexaraHaptics.select`，选中项不变时不振动）、发送与停止、审批按钮与复制在公共组件或调用点触发交互振动；状态振动由 `ChatRoute` 中的 `ChatStatusHapticTracker` 判定：UI 状态快照只负责审批提醒与运行计时（新的审批请求振动一次，等待审批不计时），完成与失败只以 `ChatViewModel.generationOutcomes` 为准——终态确认后状态会在同一次收集中回到空闲，COMPLETED 可能一帧都不出现在界面上，因此 ViewModel 在终态分支按任务 ID 只发出一次结果（完成、失败、停止）；批准后运行超过 10 秒的完成、本页看到过运行的失败各振动一次，流式输出、工具步骤、主动停止、进入或切换会话都不振动；子代理审批出现时（全局弹窗，或当前会话流内新到一项）同样给出等待审批振动。

### 新增关键组件 (2026-05-18 移植 & 调试桥落地)
- **UnifiedLlmClient**: 统一 LLM 调用入口，整合中间件链 + ToolCallLifecycleHandler，自动路由 Protocol。
- **LlmMiddlewareChain**: 可扩展中间件管线，支持 PRE/NORMAL/POST 三级 enforce 排序，链式包装 `transformStreamChunk`。

- **DsmlStreamParser**: DeepSeek DSML 格式 `<｜tool_calls｜>` XML 标签流式解析，支持跨 chunk 边界 + 缓冲区溢出保护。
- **ProviderToolFactory**: 7 个 Provider（OpenAI/Anthropic/Google/xAI/Hunyuan/DashScope）的原生 Web 搜索工具定义。
- **ToolOrchestrationPlugin**: 意图分析（关键词检测）+ 动态工具注入（web_search/knowledge_search/memory_search）。
- **ResultSizeOptimizer**: 多模态 MCP 结果 → 文本占位符转换，防 base64 超出消息大小限制。
- **MetroLogInterceptor**: 自定义 OkHttp 引擎拦截器，使用 Okio ForwardingSource 对流式 SSE (Server-Sent Events) API 响应进行非阻塞抓包，解析 chunk 并计算 Token CPS 速率。
- **MetroLoggingMiddleware**: 大模型中间件管线，拦截 `onRequestStart` / `onRequestEnd` 两个节点，高密度捕获大模型参数、滑窗历史消息和系统提示词。
- **Room QueryCallback Auditor**: 零侵入数据库 SQL 拦截。在 NexaraApplication 中直接挂载，捕获 Message / Session / TaskNode 表的所有底盘 SQL 操作。
- **scripts/nexara-metro-tui.js**: 零运行时依赖的 Node.js Debug 日志 TUI，支持 adb/标准输入、设备与 Tag 选择、TTY/非 TTY 输出、中文错误与稳定退出码。它是开发者观测工具，不是最终用户 CLI；Release 不包含可用的 Metro 调试链路。
- **Developer Panel**: 二级设置页面，用于导出日志 (`nexara_logs.txt`)。
- **Log Persistence**: 路径为应用私有 files 目录。
