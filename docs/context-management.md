# 会话上下文管理

会话设置的“上下文”标签按“上下文管理 / 检索 / 长期记忆 / 显示”分组。“上下文管理”提供自动压缩阈值、压缩后保留的最近轮数，以及“立即压缩”。默认阈值为 80%，保留最近 5 轮；阈值可选 50%–95%，每次调整 5%，保留轮数可选 1–20。阈值为值行，点开后可选 70% / 80%（默认）/ 90%，自定义 50%–95%、步长 5%；保留轮数使用行内步进器。自动压缩原理位于阈值弹层说明；分组脚注保留一条压缩摘要和不可用详情。长期记忆分组只展示已有检索开关决定的记忆来源，不增加独立写入开关或偏好。

一轮包含一条用户消息，以及它之后、下一条用户消息之前的全部助手和工具消息。最近轮数包含当前轮，当前轮始终保留。保留轮数只决定摘要边界，不限制平时发送的历史长度。

## 发送与压缩

每次请求发送系统指令（含已有历史摘要）、全部未摘要消息和当前轮，保持会话原顺序。已摘要消息不重复发送，完整记录仍可在会话中查看。工具调用与结果在发送前统一修复配对。

从已摘要历史轮重新生成时，复用的当前轮仍全文发送，包括完整文档；待替换的旧回复先排除，其它已摘要轮不重复发送。该处理只影响请求副本。

自动压缩在每次模型请求前检查，包括首轮与工具续轮；一轮结束后还会按下一次请求的内容检查。估算包含系统提示、工具定义和协议消息，使用 `ApproximateTokenEstimator`。设模型上下文为 C、输出预留为 R，预算为 `min(floor(阈值 × C), C − R)`；上下文未知时，压缩决策按 128000 token 计算。只有估算严格超过预算时才发起自动压缩。

1. 从最旧的工具结果开始折叠。正文超过 512 字符、且不属于最近 3 个工具调用轮的结果才参与，降到预算以内即停止。
2. 仍超过预算时，将最近 N 轮之前的全部未摘要消息按完整轮次总结，并与已有摘要合并。记忆开启时先归档。摘要成功后更新会话摘要并标记已摘要消息；失败则保留消息，同一生成轮内不重复尝试历史摘要。
3. 仍超过预算时再检查当前轮的可折叠工具结果，最近 3 个工具调用轮始终受保护；最终请求沿用现有上下文硬门禁。

超过 16000 字符的单条工具结果沿用私有完整输出存储与 `output_id` 分页引用。工具折叠只替换发送副本，不修改数据库正文或会话显示。折叠模型请求有超时和任务 token 预算；失败或预算不允许时使用首尾截取，并保留输出引用。

## 手动入口与模型

上下文用量面板和会话设置均可点击“立即压缩”，共用应用级压缩服务与进度流。手动操作忽略阈值，折叠所有可用候选，再总结可摘要的完整历史轮次。会话正在生成时入口禁用，同一会话的自动与手动压缩串行执行。没有候选时显示“暂无可压缩内容，最近 N 轮始终保留”。结果展示工具折叠数、摘要轮数和压缩前后估算 token。

历史摘要与工具折叠始终使用当前会话的活跃模型，自动生成使用实际路由模型，手动操作使用与生成相同的会话、智能体及默认模型解析顺序。两类压缩用量都计入摘要用量账本。

默认模型设置中的“快速模型”（偏好键 `preset_summary_model`）用于会话标题、新会话和新 Agent 的默认模型、知识图谱抽取的默认模型。上下文压缩独立使用当前会话模型。

## 兼容与存储

- `autoSummaryThreshold` 字段名与默认值 0.8 保留。`keepRecentTurns` 有值时优先使用；否则将旧 `activeContextWindow` 按 `ceil(window / 3)` 换算，并限制在 1–20；两者均缺省时为 5。例如 15 条对应 5 轮，6 条对应 2 轮。旧字段保留解码兼容，界面只写入保留轮数。
- `tool_context_ratio_percent` 和 `tool_context_keep_rounds` 不参与运行时或备份导出；含这两个键的旧备份仍可恢复，旧键被忽略。快速模型偏好继续参与备份。
- 工具折叠缓存位于应用私有的 `noBackupFilesDir/context-folds/`，按会话 ID、消息 ID、原正文 SHA-256 识别。正文改变即失效，跨轮与进程复用，删除会话时与工具输出缓存一同清理，不进入备份。
- 历史摘要复用已有 `context_summaries` 表，与消息已摘要标记在同一 Room 事务提交；重新读取会话时共同恢复，不改变数据库 schema 或版本。提交前校验旧摘要和候选原文快照，历史已变化时拒绝过期结果。记忆向量化状态独立于摘要归档。
- 删除或编辑已摘要消息会使聚合摘要失效并恢复幸存历史的发送；撤销删除恢复原文后重新参与压缩。没有合法持久摘要的旧会话会恢复全部历史参与发送和压缩，避免旧归档标记隐藏原文。
- 用量面板只读重建现有上下文与工具定义，复用已存在的折叠，不执行新检索或生成。知识增强分项沿用最近一次检索计数，下一次请求的新检索内容尚不可知。token 数为近似估算；最终提供商用量与现有上下文硬门禁分别保留。截图与 JVM 检查不能替代真实模型、设备和跨进程运行验收。
