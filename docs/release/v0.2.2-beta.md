# Nexara v0.2.2-beta 发行说明

> 发布状态：PENDING
> 版本身份：versionCode `4` / versionName `0.2.2-beta`
> GitHub APK 发布：尚未授权

Nexara 是 Android 12+ 的 BYOK AI 客户端，提供多服务商流式对话、完整文档上下文、Agent 工具、会话工作区、RAG、知识图谱和手动加密备份。当前版本为本地签名候选，验证及制品身份见[验证账本](v0.2.2-beta-validation.md)。本文件不构成 tag、GitHub Release 或公开资产发布授权。

## 功能与交互

- 知识库集中呈现索引和图谱任务的进度、错误、重试、取消与配置入口，错误状态不会被当成持续索引；文件按当前目录平铺，下钻及面包屑返回复用同层浏览方式。
- 会话工作区与知识库保持身份和索引边界，用户可显式转存文件到知识库；会话文件不会默认进入知识库自动向量化流程。
- 首页、设置、智能体及知识库采用统一操作菜单与导航样式，任务状态保持可见。
- 提示词编辑器支持编辑、预览、行号与滚动，修复 Android 12 上编辑页面可能持续布局的问题。
- 模型目录支持独立签名更新，验签缓存保留用户编辑；维护方式见[模型目录说明](../model-catalog.md)。
- 文件事务身份、备份恢复、双库恢复、完整文档发送及会话分支的行为合同沿用项目实现；每项当前验证范围由账本单独列明。
- Agent 长任务：工具轮次支持“不限”并配单任务 token 预算与重复调用暂停，首次“不限＋全自动”需要明确确认；审批可保存本会话目标授权；早期工具结果按上下文比例压缩，大输出存入会话私有存储；聊天页与前台通知显示进度。
- 外部文件夹挂载：两个渠道均可通过 SAF 授权文件夹，侧载渠道另可在授予所有文件访问后挂载共享存储真实路径；工作区工具经 `/mnt/<别名>` 访问，带版本冲突拒绝、回收区与显式不可恢复删除审批。
- 原生 SSH：主机管理（密码、Ed25519、OpenSSH 私钥导入，首次指纹确认与变化拦截）、`ssh_exec`、SFTP 列表/读取/条件写入、常驻 PTY 工具、用户终端及仅监听 `127.0.0.1` 的端口转发；审批绑定主机身份与完整命令或路径。
- 隔离脚本：`exec_js` 与 `run_script` 在隔离进程 QuickJS 中执行，默认 30 秒、上限 300 秒，联网须显式开启，文件能力复用工作区与挂载审批。
- Termux 集成（默认关闭）：`termux_exec` 经 RUN_COMMAND 在用户自行安装的 Termux 中运行 bash；设置页提供诊断、权限与 SSH/SAF 引导；可选本机 `127.0.0.1` HTTP MCP，访问令牌必填。
- 知识图谱进入聊天检索：按会话可见证据检索持久图并一至两跳扩展，与即时抽取结果融合并受预算裁剪；图谱页支持大图分页加载、实体搜索与按需展开。

## 安装与覆盖升级

发行工作流准备侧载主资产 `nexara-v0.2.2-beta.apk` 与 Play 风味资产 `nexara-v0.2.2-beta-play.apk`，各自附独立 `.sha256`。两个渠道共享包名与发行证书，仅侧载制品声明所有文件访问权限，用于真实路径挂载；Play 制品只提供 SAF 授权挂载。构建命令、mapping 路径及按渠道验收入口见[发行渠道构建说明](../distribution-builds.md)；任务配置不代表已生成新签名候选或已经公开发布。

发行身份为 `com.promenar.nexara.native` / code `4` / `0.2.2-beta`。维护者交付 APK 时必须提供源码 SHA、APK 大小与 SHA-256、登记证书验真结果及同一制品的验证证据。当前本地签名 APK 的路径、哈希与验证范围登记在验证账本；仓库根目录 APK 或历史制品不自动作为当前候选。

已有同包名、同发行证书的旧版应先保存完整备份，再覆盖安装；不卸载、不清数据。公开 v0.1-beta 的数据库为 v17，v0.2-beta 为 v2；当前迁移目标为 v21（v19 知识图谱证据、v20 外部挂载、v21 SSH 主机配置），双库恢复候选仍以 v18 身份校验。曾经过 v0.1→v0.2 的安装可能同时保留两库，启动页使用显式“保留两份并恢复”入口。历史迁移证据见 [v0.2.1-beta 验证账本](v0.2.1-beta-validation.md)，当前 APK 的升级验收必须独立记录。未知签名、不同包名或被重签名的 APK 不能作为正常覆盖升级来源。

## 使用边界

- 物理真机 TalkBack 听觉、完整焦点遍历与 OEM/IME 体验需要人工验收，模拟器和静态检查不能替代。
- Release Provider 和 WebDAV 仅允许 HTTPS；用户密钥由设备 SecretStore 管理，默认不纳入备份，包含完整密钥时备份必须加密。
- 个人与 Agent 自定义头像属于设备本机资产，不跨设备备份。
- WebDAV 是手动备份与恢复；后台生成覆盖前台发起的单个当前任务，设备重启续传、多会话并行及无人值守队列不在稳定范围。
- GGUF/llama.cpp 本地推理属于实验性资产，不随 Release 提供稳定能力。
- 内置 Mermaid 需要系统 WebView（Chromium）94 及以上；更旧的 WebView 上流程图回退显示源码，公式与图表不受影响。
- SFTP 的 `expected_sha256` 条件写入在客户端校验后写入，SFTP 协议不提供跨客户端原子比较写入；侧载真实路径覆盖写入在校验与替换之间存在短暂窗口，并发外部修改无法完全排除。
- Termux 能力依赖用户自行安装 Termux 并授予 RUN_COMMAND 权限，应用不附带 Termux；未内置 Python 运行时，需要时经 Termux 或 SSH 使用。
- 历史真实服务结果不证明当前全部 Provider、工具、多模态或检索指标通过；模型或网关失败与未测试的产品指标必须按账本披露。

公开发布需要用户明确授权，账本与说明精确 GO、登记的人工风险接受、同一签名制品的冷安装与覆盖升级证据，并由受保护 workflow 完成构建、设备门禁及资产上传回读。手动 workflow_dispatch 仅验证候选。
