# 安装、升级与数据迁移

> 所属：[使用指南](README.md)。仓库首页只介绍概览，本文给出完整说明与边界。

## 运行要求

| 项目 | 要求 |
|---|---|
| Android | Android 12 及以上（API 31+） |
| 目标 SDK | API 36 |
| 存储 | 建议至少保留 200 MiB；导入文档另计 |
| 网络 | 云端模型、Embedding、Rerank、联网搜索和 WebDAV 需要网络 |
| 权限 | 网络；通知权限用于后台生成，可拒绝但会退化为仅前台生成 |

Infinity Workbench 使用 `com.promenar.infinity`，与旧应用并存。备份导出目前有已知缺陷，修复前建议卸载旧应用后在新应用中重新配置；修复后可在旧应用导出备份，再在新应用导入；加密备份使用导出时设置的密码。新备份名为 `infinity_backup_<13 位时间戳>.iwb`，导入与远程列表同时接受旧 `.nexara` 备份。交付 APK 必须核对登记的发行证书。以下旧版数据库升级事实仅用于解释历史数据结构，不表示不同应用 ID 可以覆盖升级。公开 `v0.1-beta` 的数据库为 v17，公开 `v0.2-beta` 为 v2；当前库提供前进迁移到 v23，版本链为 v18→v19（知识图谱实体与证据）→v20（外部挂载与快照）→v21（SSH 主机）→v22（自选工作区登记、会话与 Agent 的工作区绑定、Agent 用户规则及其历史）→v23（对话图谱证据的所属消息及索引、会话按助手的索引）。安装曾经过 `v0.1-beta→v0.2-beta` 时，两份数据库分别保全，启动页提供显式“保留两份并恢复”入口。双库恢复候选保持独立的 v18 合同，完成恢复后由主库迁移到 v23。恢复保留两侧业务和来源，冲突 ID 重映射关联，工作区建立新物理身份，合法旧附件可点击读取；未完成工具和索引任务等待用户重试。`v0.2.1-beta` 的公开单库及三段双库升级合成数据证据属于[历史验证](../release/v0.2.1-beta-validation.md)，不能代替当前候选 APK 或真实用户资料验收。真实安装应保留完整备份，不卸载、不清数据；来源不同、被重签名或包名不同的 APK 不能正常覆盖继承。

## 安装

公开制品只从 [Promenar/Infinity Workbench Releases](https://github.com/Promenar/Infinity-Workbench/releases) 发布，由发行工作流在推送版本标签后构建、验签并上传；早期 `v0.1-beta` 与 `v0.2-beta` 发行已于 2026-10-30 下线。公开发布可能落后于源码。安装时：

1. 取得维护者交付并验真的 APK 与对应 `.sha256` 文件；侧载主资产为 `infinity-v<版本>.apk`，Play 风味资产为 `infinity-v<版本>-play.apk`，Release 说明中列出两者的 SHA-256。
2. 校验 APK 的 SHA-256 与发布文件一致。
3. 在 Android 系统中允许当前文件管理器或浏览器“安装未知应用”。
4. 安装 Infinity Workbench 后，在旧应用导出备份并导入新应用。确认数据完整前保留旧应用；不同应用 ID 不能覆盖升级。同 ID 的后续版本可按同签名覆盖安装。

不要安装 Actions 临时制品、Debug APK 或来源不明的重打包版本。
