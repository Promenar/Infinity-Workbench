# Infinity Workbench 移动工作流能力测试方案

日期：2026-10-31。适用环境：Android 真机（内置 Tailscale 节点）、tailnet 内两台 Linux 测试主机，以及开发契约允许的本机模拟器。文档性质：测试设计与执行入口，不是能力通过声明。

## 1. 目标与判定口径

验证使用者能否在 Infinity Workbench 中完成原由桌面 ADE（Codex、Claude Code 等）承担的日常工作：接收材料、加载技能与规则、规划、调用工具、检查结果、修订、导出和恢复任务。

任务按负载分三档，判定要求不同：

| 负载 | 完成路线 | 判定要求 |
| --- | --- | --- |
| 轻型 | 手机直接完成：文件工具、内置 shell/Python、隔离脚本、Termux | 必须 PASS；与桌面 ADE 的差距按缺口登记 |
| 中型 | 手机调用服务完成：模型、OCR、生图、TTS、文档转换由既有服务承担，手机组织任务并验收 | 必须 PASS；记录实际依赖的服务 |
| 重型 | 手机调度远端完成：经 SSH 在测试主机运行有界任务并取回结果 | 必须 PASS；产物能取回核对即满足产物要求，不考核耗时与性能 |

PASS 同时要求产物与执行过程两方面达标：任务产物完整、通过验收，并且执行过程中的交互达到桌面 ADE 的水平。交互按下列七项逐项评判，结果记为具备、部分或缺失，并附证据：

| 交互项 | 达标表现 |
| --- | --- |
| 过程可见 | 计划、工具调用、进度和输出在执行中可以查看 |
| 可中断 | 能随时停止当前任务，停止后不再产生新副作用 |
| 可中途介入 | 执行中能编辑指令、插队、批准或拒绝动作 |
| 可挂起与恢复 | 任务能停在等待状态（审批、提问、外部结果），条件满足后继续 |
| 后台作业可轮询 | 长时作业在后台运行时能查询进度并取回结果 |
| 中断后可恢复 | 切后台、锁屏或进程被结束后，状态准确，能继续或明确终止 |
| 失败可定位 | 失败时能看到原因和出错的步骤 |

产物正确但任一交互项为部分或缺失时，记 `GAP_PRODUCT` 并写明缺的是哪一项，不记 PASS；与该任务无关的交互项记为不适用并说明理由。七项适用于全部端到端任务（W1–W20），以及执行类基础条目（A6、A7、A8、D4、D5、H1–H3）。

同一项能力只在最贴近真实使用的条目中测一次：服务已由某个端到端任务覆盖时，不再单设服务条目；“计划→执行→检查→修订”是所有端到端任务的必经环节，不单列。

### 1.1 范围外

| 项目 | 依据 |
| --- | --- |
| 数字人口播 | 本质是视频生成，由 F5 覆盖；用户决定不单测 |
| Windows 与 macOS 的 SSH 后端 | 用户决定本轮只配置两台 Linux 测试主机 |
| 手机本地重型编译、训练、GPU 推理，桌面软件完整移植 | 不属于移动端目标；重型任务走远端（W19、W20） |

范围外项目不计入通过率，也不得以“不适用”掩盖范围内的产品缺口。

## 2. 当前合同与证据来源

执行批次必须登记实际源码 SHA、工作树差异和安装包身份。编制时的源码为 `2529b0a3`，真机安装 `0.8.0-beta`（versionCode 27）。B0 先按下列来源复核合同，与本文不一致时以代码为准并回写本文。

当前审批合同（`ToolExecutionPolicy`、`ToolArgumentApprovalRules`）：

- 权限分两档：“命令需批准”（代码中为工作区档）下，命令类工具（`shell_exec`、`python_exec`、`termux_exec`、`ssh_exec` 等）逐条审批；“免批准”（完全访问档）下命令不再审批。
- 测试统一在“命令需批准”档执行；只有 D3 需要对比两档的审批差异，两档都跑。
- 与档位无关、每次都要审批：定时任务创建（`schedule_create`）、知识访问授权（`request_knowledge_access`）、SSH 主机配置（`ssh_host_save`、`ssh_host_delete`、`ssh_host_install_key`）、技能目录变更、启动问题处置。
- 外部文件夹挂载属于当前会话且可读写；SAF 路径只对文件工具可见，命令能否看到真实路径需分别验证。工作区档不对真实命令施加路径沙箱。

## 3. 测试环境

### 3.1 设备与主机

| 别名 | 角色 | 用于 |
| --- | --- | --- |
| 真机 | Android 真机，应用内置 Tailscale 节点 | 全部条目 |
| 模拟器 | 本机 Android 模拟器 | 需要清数据、强停、升级等破坏性生命周期条目 |
| `fnos` | Linux 测试主机（NAS） | Linux SSH 后端、SFTP、TTS、SSH Git 测试远端、文档转换 |
| `main-linux` | Linux GPU 主机（Ubuntu、RTX 4090，运行 ComfyUI） | 重型远端任务、生图、媒体处理、远端构建 |

真实地址、账号、端口与测试目录登记在本地服务映射（不入仓库）。应用内 SSH 主机别名与上表一致。

### 3.2 SSH 免密配置

应用为每个 SSH 主机单独生成 ed25519 密钥。两台测试主机的配置方式：

1. 在应用 SSH 主机设置中“从 Tailscale 选择”目标设备，认证方式选密钥并生成。
2. 公钥追加到目标主机 `~/.ssh/authorized_keys`，行首限定 `from="<手机 tailnet 地址>"`，注释为 `infinity-<设备节点名>:<主机别名>`；追加前备份原文件。
3. 手机首次连接时核对主机指纹，与开发机 `ssh-keyscan` 计算的指纹一致才信任。
4. 撤销：删除带对应注释的那一行；应用内删除主机即删除本机私钥。

Git SSH 测试远端是 `fnos` 测试目录下的裸仓库，不使用生产仓库。

### 3.3 服务映射

用服务别名登记同一服务池，每个服务记录：能力类别、桌面调用入口、手机调用入口、协议/TLS、认证方式名称、输入输出位置、费用与额度、无副作用探针、允许的测试动作、取回与清理方法。至少登记模型网关（含嵌入与重排）、搜索、OCR、图像生成、视频生成、TTS、文档/媒体处理、MCP 工作台、Git 远端、两台 SSH 主机。

### 3.4 材料包

每个包固定版本、SHA-256、独立预期结果与错误样本。优先合成数据；业务输入只用获准副本。真实凭据、Cookie、私钥和完整敏感日志不得进入模型、附件或提交。

| 材料包 | 组成与独立验收依据 |
| --- | --- |
| F-SKILL | 含 `references/`、标准库脚本和相对引用的技能；同名两级版本、禁隐式调用、内容修改、损坏与超限样本 |
| F-FILES | 中文/空格/emoji 名称、嵌套目录、重复文件、超预览限制的长文本与大文件；已知哈希 |
| F-OFFICE | PPTX、DOCX、XLSX、文本 PDF、扫描 PDF、两版合同；含已标注的计算与引用错误；独立金标准 |
| F-BUDGET | 合成台账、状态规则、月度铺排与预算模板 xlsx；约 20 行的精简 CSV；总量、分类与勾稽的独立预期值 |
| F-BRAND | 虚构品牌、许可明确的字体/标志/菜品参考、准确文案、尺寸与禁改元素 |
| F-STORY | 虚构人物与场景、已采用与候选事实、短剧剧本、配音台词与合法声音参考 |
| F-REPO | 可丢弃的小仓库：带一个可复现缺陷与轻量测试、可制造分叉的分支 |
| F-KNOW | 两个隔离项目的资料：明确日期与来源、新旧冲突信息、删除与更新样本 |
| F-MEDIA | 合法图片、10 秒视频、音频；已知尺寸、时长、帧率、音轨与哈希；另含损坏样本 |

## 4. 优先级与结果

| 优先级 | 含义 |
| --- | --- |
| P0 | 接手日常工作必须可靠的链路与任务；相关改动进入高频回归 |
| P1 | 完整迁移范围内的重要能力；材料与服务就绪后分批验收 |
| P2 | 实验能力或拓展路线；单独报告 |

所有条目初始为 `NOT_RUN`，结果写入批次记录，本文不承载滚动状态。

| 结果 | 判定 |
| --- | --- |
| NOT_RUN | 未执行，或只有不适用当前批次的历史证据 |
| PASS | 指定输入、配置和路线下，行为与交付物均满足通过标准 |
| FAIL | 已具备执行条件，但行为或结果违反通过标准 |
| BLOCKED_ENV | 服务、材料、授权、预算、账号或设备条件未就绪；登记缺项 |
| GAP_PRODUCT | 桌面目标成立，但应用缺少完成任务的产品能力或接入链路 |
| GAP_ADAPTER | 应用底座可承担，但技能、脚本或协议适配缺失 |
| NOT_APPLICABLE | 合同明确排除（如 Play 渠道不提供的侧载能力），必须注明依据 |

| B2 | 第 5 节 A–E、G、H 其余条目 | 输入、工具、文件、网络、上下文与恢复链路有实际证据 |

| B4 | 第 6 节端到端任务：先轻型，再中型，最后重型 | 有实际成品与修订往返，关键结论可复核 |
| B5 | 第 7 节变体中尚未覆盖的组合，以及资源与跨端接续 | 无数据损失、秘密暴露或错误副作用等未处理阻断 |

B2、B3 中无依赖的条目可以交错执行；共享文件、模型/GPU 队列、真机安装与 Gradle 串行协调。不为覆盖清单制造真实客户副作用。

## 9. 执行记录与缺陷回流

每批在 `docs/testing/runs/<批次标识>/report.md` 保存脱敏结论；大体积截图、日志与 APK 放项目 `artifacts/` 忽略区，不把秘密或业务原件提交到仓库。

| 字段 | 内容 |
| --- | --- |
| 批次与时间 | 唯一批次标识、含时区的真实执行时间 |
| 版本 | 源码 SHA、工作树差异摘要、APK SHA-256、包名、版本、签名身份与渠道 |
| 设备 | 系统、设备别名、ABI、WebView、后台与通知设置 |
| 模型与执行 | 模型/网关别名、权限档、工作区类型、执行后端、技能版本 |
| 服务与输入 | 服务映射版本、材料包版本与哈希、授权与预算边界 |
| ID 与变体 | 条目 ID、变体 ID、实际操作与额外人工步骤 |
| 独立预期 | 金标准或业务不变量、外部阅读/播放检查、允许误差 |
| 实际结果 | 状态码、退出码、必要的脱敏响应、产物位置与哈希、质量判断 |
| 交互评判 | 第 1 节七个交互项逐项记为具备、部分、缺失或不适用，每项附证据（截图、时间点、操作记录）；部分或缺失时写明差在哪里 |
| 成本与性能 | 时间、人工介入次数、资源、token、已知费用与缺失项 |
| 证据与结论 | 截图、日志、命令、成品引用；结果枚举、差异、复核者 |
| 缺陷与后续 | 问题归类（产品、适配、服务、环境、模型、材料、操作），关联条目、责任范围与复测条件 |

不得只记录成功截图。每项判定至少包含实际输入、操作、可核查输出与独立预期；模型声称完成不是证据。环境失败与产品失败分开计数。

## 10. 与现有自动化的关系

文档维护不启动以下任务。开发验证按 [PDEC](../../.pdec/README.md) 与[发行渠道说明](../distribution-builds.md)选择入口，不争用同一工作树的 Gradle、安装包和设备。

| 范围 | 入口 | 可证明与不能替代的范围 |
| --- | --- | --- |
| JVM 与设备源码 | `native-ui/app/src/test/`、`native-ui/app/src/androidTest/` | 权限、路径、技能、命令、tailnet、SSH、备份等有测试入口；文件存在不代表通过 |
| JVM / Lint / 截图 | `:app:testSideloadDebugUnitTest`、`:app:testPlayDebugUnitTest`、`:app:lintSideloadDebug`、`:app:validateSideloadDebugScreenshotTest` | 绑定代码的自动化证据；不代替真实远端、媒体效果与业务成品 |
| 设备综合脚本 | `scripts/ci/android-device-core-e2e.sh` | 会构建、安装并清空测试应用数据，只用于模拟器或专用测试设备 |
| 混淆黑盒 | `scripts/ci/android-minified-blackbox-smoke.sh` | 混淆产物的黑盒路径；不能直接套用到另一签名 APK |
| 安装与升级 | `scripts/ci/android-release-apk-smoke.sh`、`scripts/ci/android-release-upgrade-smoke.sh` | 安装身份与升级数据链路；操作前确认数据保护与目标设备 |
| 发行清单 | `scripts/ci/check-distribution-manifests.py`、`scripts/verify-release-apk.py` | 渠道与制品身份；不证明端到端工作完成 |

## 11. 完成声明

阶段报告分别给出：基础能力覆盖、每个服务的真实调用结果、端到端任务交付（按轻、中、重分列）、交互评判汇总（七个交互项各自在哪些任务中部分或缺失）、故障与资源边界、未解决缺口。

轻、中、重三档任务全部 PASS，也就是产物达标且七个交互项均具备（或有理由不适用），才可以称“日常非重型工作可在手机完成，过程可控程度与桌面 ADE 相当”。只有产物达标而交互有缺失的任务，单独列为“能做成但过程不可控”，不计入通过。中型任务允许服务承担其天然计算职责，但报告须写明依赖；流程中任何一步必须回到桌面 ADE 人工补做的，该任务不能记为完整移动交付。范围外项目与实验能力单列，不混入必达统计。
