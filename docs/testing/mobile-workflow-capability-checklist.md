# Infinity Workbench 移动工作流能力测试清单

日期：2026-10-24。适用环境：Android 手机、同网络环境下的既有服务，以及开发契约允许的本机模拟器。文档性质：测试设计与执行入口，不是能力通过声明。

## 1. 目标与范围

验证使用者能否在 Infinity Workbench 中完成原由桌面 ADE 承担的项目开发、经营资料处理、内容创作和日常服务协作：接收材料、加载技能与规则、规划、调用工具、检查结果、修订、导出和恢复任务。

环境前提由使用者提供：手机与开发笔记本处于同一网络环境，可测试的既有远端服务池相同。将桌面已能调用的服务纳入迁移目标；实际连接、认证、协议和文件传递是否等价，由对应测试取证。同网络不代替应用权限、工具接入及运行时兼容性验证。

三种完成路线分别记账，不互相冒充：

| 路线 | 含义 | 典型任务 |
| --- | --- | --- |
| 手机直接完成 | Infinity Workbench 文件工具、隔离脚本、内置命令或手机 Termux 完成处理 | 文本、结构化数据、轻量代码、技能、HTML/SVG、Git |
| 手机调用服务完成 | Infinity Workbench 组织任务，既有服务承担模型、OCR、文档处理或媒体计算 | 搜索、推理、生图、视频、TTS、文档转换 |
| 手机调度远端完成 | Infinity Workbench 经既有 SSH/MCP 等入口管理有界任务并取回结果 | 远端脚本、验证、渲染与服务诊断 |

重负载编译、训练、手机本地 GPU 推理、桌面软件的完整功能移植不属于必达目标。可以验证手机发起远端构建与读取结果，但不要求在手机本地完成重型构建。已允许通过服务完成的任务，不强制改为手机本地计算。

本清单的维护不授权实际付费生成、生产启停、安装依赖、创建网络入口、修改业务原件或对外发布。执行时沿用当前任务授权、费用预算和目标服务的安全边界；破坏性与故障注入测试使用测试副本及隔离目标。

## 2. 当前合同与证据来源

编制时核对的源码基线为 `551a12a435ad17db52411f1ee1dce2aa5b1f5e43`；存在其他开发工作尚未提交的改动。该 SHA 仅标识调查时间点，不是执行批次绑定。执行批次必须登记实际源码、工作树差异和安装包身份。

当前产品合同：

- 权限为“工作区 / 完全访问”两档。工作区内文件工具和隔离脚本按工作区范围执行；真实命令在工作区档逐条审批。完全访问档的命令免审批。技能目录变更、定时任务创建、SSH 主机配置按专项规则审批。
- 外部文件夹属于当前会话且可读写；SAF 路径只对文件工具可见，真实路径的命令可见性需分别验证。工作区档不是对真实命令施加路径沙箱。
- MCP 与 `web_fetch` 的运行时审批行为按当前合同验证，不把已删除的审批白名单、只读挂载或三档模式作为验收要求。
- 手机系统约束、后台保障、脚本依赖和侧载/Play 差异按当前实现与真实设备取证，不从桌面环境推导。

## 3. 优先级、状态与判定

| 优先级 | 含义 |
| --- | --- |
| P0 | 接手实际工作必须可靠的基础链路与关键任务；相关改动进入高频回归 |
| P1 | 完整迁移范围中的重要任务与远端能力；对应材料和服务就绪后分批验收 |
| P2 | 已声明的实验能力、拓展路线或不要求手机独立承担的负载；单独报告 |

所有条目初始为 `NOT_RUN`，执行结果写入批次记录，清单本体不承载滚动通过状态。

| 结果 | 判定 |
| --- | --- |
| NOT_RUN | 未执行，或只有不适用当前批次的历史证据 |
| PASS | 指定输入、配置和路线下，技术行为及交付物验收均满足要求 |
| FAIL | 已具备执行条件，但行为或结果违反验收标准 |
| BLOCKED_ENV | 目标服务、材料、授权、预算、账号或设备条件未就绪；登记缺项 |
| GAP_PRODUCT | 桌面目标成立，但 Infinity Workbench 缺少完成任务的产品能力或接入链路 |
| GAP_ADAPTER | Infinity Workbench 底座可承担任务，但技能、脚本或协议适配缺失 |
| NOT_APPLICABLE | 明确合同排除，例如 Play 不提供的侧载能力；必须注明依据 |

产品缺口和适配缺口属于待完成范围，不能改记为“不适用”来提高通过率。没有执行全部目标时，只报告已验证范围，不发布“桌面能力完整迁移”结论。

## 4. 测试材料与服务登记

### 4.1 合成材料包

每个包固定版本、SHA-256、预期结果和错误样本。下面是待准备的输入规格，不代表材料已经生成或业务任务已经执行。

| 材料包 | 最小组成与独立验收依据 |
| --- | --- |
| F-SKILL | 含参考文件、脚本和相对引用的技能；两级同名、禁隐式调用、内容修改、损坏及超限样本 |
| F-FILES | 中文/空格/emoji 名称、嵌套目录、重复文件、长文本、大文件及冲突副本；已知内容哈希 |
| F-OFFICE | PPTX、DOCX、XLSX、文本 PDF、扫描 PDF；包含表格、图表和已标注计算/引用问题；独立金标准 |
| F-BUDGET | 合成台账、状态规则、月度铺排与预算模板；总量、分类、公式和勾稽的独立预期值 |
| F-BRAND | 虚构品牌、许可明确的字体/标志/菜品参考、准确文案、尺寸和禁改元素 |
| F-STORY | 虚构人物与场景、已采用事实和候选事实、短剧剧本与完整文字分镜、配音台词及合法声音参考 |
| F-REPO | 可丢弃的小仓库、轻量测试、分支冲突和跨端修改副本；不使用生产项目作为破坏性夹具 |
| F-KNOW | 两个隔离项目、明确日期和来源、互相冲突的新旧信息、删除与更新样本 |
| F-MEDIA | 合法图片、短视频和音频；已知尺寸、时长、帧率、音轨与哈希，另含损坏媒体 |

材料优先使用合成数据；业务输入使用获准的副本。商标、人物、声音、客户资料和公开发布权限分别核对。真实凭据、Cookie、私钥和完整敏感日志不得进入模型、测试附件或提交内容。

### 4.2 既有服务映射

用服务别名映射同一服务池，不在公开文档保存真实内部地址、账号、私有路径或凭据。每个服务登记：能力类别、桌面调用入口、手机调用入口、协议/TLS、认证方式名称、输入输出位置、运行时依赖、费用与额度、无副作用探针、允许的测试动作、取回与清理方法。

至少登记模型网关、搜索、OCR、文件存储、图像生成/编辑、视频生成、TTS、媒体/文档处理、MCP 工作台、浏览器执行环境、在线文档、Git、SSH 主机和监控入口。桌面 ADE 的内置工具及已登录浏览器也属于接入差异调查对象；不能因为手机处于同网络就假定已获得这些工具。

## 8. 故障、资源与交付变体

每个相关场景标注所执行的变体 ID。故障注入限测试服务与副本，不在生产上制造断电、杀进程、耗尽磁盘或更换证书。

| ID | 操作 | 必须观察的结果 |
| --- | --- | --- |
| X-01 | 调用前/执行中断网、恢复网络、切换网络 | 无重复提交与伪成功；已完成和待恢复状态可核对 |
| X-02 | 401/403、过期登录、失效 SSH 信任或证书错误 | 认证、权限、TLS 分开归因；不自动放宽安全设置 |
| X-03 | 429、超时、服务 5xx、成功响应但任务失败 | 有界重试和明确终态；写操作不盲重放；失败原因能取证 |
| X-04 | 用户拒绝审批、取消、停止父任务或工具 | 已批准/已执行范围准确；取消传播及释放资源；不产生新副作用 |
| X-05 | 同一任务重复提交、重复通知与重复回包 | 任务身份可追踪；重复副作用可发现并按合同抑制 |
| X-06 | 源文件变更、并发编辑、跨设备版本冲突 | 保留正确版本及恢复副本；不静默丢失用户内容 |
| X-07 | 长上下文、大文件、大输出、长耗时或资源不足 | 分页/压缩/预算/部分结果准确；没有截断后误报完整 |
| X-08 | 锁屏、省电、进程结束、前台恢复 | 区分操作系统暂停、任务终止和可恢复状态；无假运行 |
| X-09 | 文件、网页、技能或工具结果中出现越权指令 | 内容不能自行扩大授权、读取秘密或操纵其他项目；需要边界的执行器实测 |
| X-10 | 内容正确但文件损坏、字体缺失、媒体参数不符 | 产物验收能失败；生成成功、哈希一致不代替阅读/播放/视觉检查 |
| X-11 | 多 Agent 争用文件、超预算、子任务迟到回片 | 输出归属和版本准确；父任务不误采过期结果；冲突可处理 |
| X-12 | 手机操作过长、需横向表格/输入法/大字号/TalkBack | 关键内容可读、动作可达、输入不丢；人工介入与桌面补救如实记录 |

性能不预设没有依据的统一秒数。先用同一输入建立桌面基线，记录端到端时间、首响应、设备电量/温度/内存、网络量、模型 token 和已知费用；再按实际工作容忍度设定具体预算，执行前写入批次。未知费用保留未知，不按 token 或估计单价伪造实收成本。

| B3 | SV 系列既有服务；每个独立服务按“探针→任务→取回”执行 | 每个桌面目标得到 PASS、缺口或环境阻断判定 |
| B4 | WF 系列逐项工作；至少一个完整综合交付 | 有实际成品及修订往返，关键结论可复核 |
| B5 | 故障变体、相称的容量/资源与跨端接续 | 无数据损失、秘密暴露或错误副作用等未处理阻断 |

B2/B3 中无依赖的条目可以交错执行；共享文件、模型/GPU 队列、生产服务和设备安装串行协调。不为覆盖清单而制造真实客户副作用。

## 10. 执行记录与缺陷回流

每个批次使用 `docs/testing/runs/<批次标识>/report.md` 保存脱敏结论；大体积截图、视频、APK、日志沿用项目 `artifacts/` 的忽略区与既有制品归档约定，不把秘密或业务原件提交到公开仓库。

记录模板：

| 字段 | 内容 |
| --- | --- |
| 批次与时间 | 唯一批次标识、含时区的真实执行时间 |
| 版本 | 源码 SHA、工作树是否有差异/差异摘要、APK SHA-256、包名、版本、签名身份与渠道 |
| 设备 | 系统、机型/测试设备别名、ABI、WebView、后台与通知设置 |
| 模型与执行 | 模型/网关别名、权限档、工作区类型、执行后端、技能及适配版本 |
| 服务与输入 | 服务映射版本、输入包版本/哈希、授权与预算边界 |
| ID 与变体 | 清单 ID、X 系列变体、实际操作和额外人工步骤 |
| 独立预期 | 金标准/业务不变量、外部阅读或播放检查、允许误差 |
| 实际结果 | 状态码、退出码、必要脱敏响应、产物位置/哈希和质量判断 |
| 成本与性能 | 时间、人工介入次数、资源、token、已知费用及缺失项 |
| 证据与结论 | 截图/日志/命令/成品引用，结果枚举、差异、复核者 |
| 缺陷与后续 | 产品/技能适配/服务/环境/模型/材料/操作问题，关联清单 ID、责任范围和复测条件 |

不得只记录“成功截图”。每项判定至少包含实际输入、操作、可核查输出和独立预期；模型声称完成不是证据。环境失败与产品失败分别计数，同时保留全部未通过目标。

## 11. 与现有自动化的关系

文档维护不启动以下任务。开发变更需要验证时，按 [PDEC](../../.pdec/README.md) 和 [发行渠道说明](../distribution-builds.md) 选择当前适用入口；测试串行协调，不争用同一工作树的 Gradle、安装包和设备。

| 范围 | 已核对的入口 | 可证明与不能替代的范围 |
| --- | --- | --- |
| JVM 与设备源码 | `native-ui/app/src/test/`、`native-ui/app/src/androidTest/` | 权限、路径、技能、命令、tailnet、SSH、备份等存在测试入口；文件存在不代表执行通过 |
| JVM / Lint / 截图 | `:app:testSideloadDebugUnitTest`、`:app:testPlayDebugUnitTest`、`:app:lintSideloadDebug`、`:app:validateSideloadDebugScreenshotTest` | 对绑定代码的自动化证据；不代替真实远端、媒体效果和业务成品 |
| 设备综合脚本 | `scripts/ci/android-device-core-e2e.sh` | minimum/full、指定 ABI 与目标设备；脚本会构建、安装并清空测试应用数据，须使用合适目标 |
| 混淆黑盒 | `scripts/ci/android-minified-blackbox-smoke.sh` | 混淆产物的黑盒路径；不能直接套用到另一个签名 APK |
| 安装与升级 | `scripts/ci/android-release-apk-smoke.sh`、`scripts/ci/android-release-upgrade-smoke.sh` | 安装身份和升级数据链路；操作前确认数据保护与目标设备 |
| 发行清单 | `scripts/ci/check-distribution-manifests.py`、`scripts/verify-release-apk.py` | 渠道与制品身份；不证明端到端工作完成 |

## 12. 完成声明

阶段报告分别给出：基础能力覆盖、每个服务的真实调用结果、端到端任务交付、故障与资源边界、未解决缺口。只有输入到交付的全过程均有证据，才称该工作流可在手机完成。

“手机可完成”允许服务承担其天然计算职责；报告必须写明依赖。若流程中的必要一步仍需回到桌面 ADE 人工补做，则该场景不能标记为完整移动交付。原本不属于目标的重负载本地编译、已明确标为实验的能力及渠道排除项单列，不混入必达能力统计。
