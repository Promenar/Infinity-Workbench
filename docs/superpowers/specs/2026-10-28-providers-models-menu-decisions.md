# 提供商与模型管理页、悬浮菜单：界面决定

- 状态：已确认（2026-10-28）
- 原型：[提供商模型页与悬浮菜单原型](https://claude.ai/artifact/L8ohfDd3NQqXsbt2umNT5r)（私有 Artifact，含提供商列表、添加 / 编辑提供商、模型列表、编辑模型五屏流程，以及悬浮菜单现状与重设计对比）
- 用途：W2-M 的界面依据。路径相对 `native-ui/app/src/main/java/com/promenar/nexara/`。

## 1. 提供商

- D1 提供商列表去掉与页面标题重复的分组标题“AI 与模型”，改为一行概况，如“4 个提供商 · 3 个已启用”；全部提供商在一张连续分组卡片里。
- D2 提供商行分三段信息：名称与状态标签、协议与主机名、凭证与模型数。头像为 40dp 圆角方块；地址只显示主机名（等宽字体，去掉 `https://`）；“已停用”“协议不受支持”用标签表示，未配置密钥用警示色；新增“启用 4 / 7 个模型”。另显示最近一次连接测试的结果与时间，例如“连接正常 · 2 小时前”。
- D4 提供商保存方式不变：保留底部“测试连接 / 保存”操作栏，测试结果改为贴在操作栏上方的状态条。
- D5 表单去掉双层框：新增无框输入行，放进分组卡片。标签在上、输入在下，聚焦时标签变为主色，底部出现 2dp 指示线；出错时整行转为错误色，并在下方写出原因。
- D6 提供商表单按“提供商 / 接口 / 凭证 / 高级”四组重排：
  - “会话请求头”分组标题改为“高级”，开关保留原名，并加一行说明；
  - 悬空的“安全存储”一行改为凭证组脚注“密钥保存在本机安全存储中”；
  - 预设提供商从 Material 原生下拉改为底部面板选择，与协议类型的选择方式一致；
  - `ProviderApiSourceSection` 的分段与 Tailscale 状态行并入“接口”分组卡片。

## 2. 模型

- D7 模型列表顶部：
  - “添加”移到顶栏 +，与提供商列表一致；
  - “全部禁用”“全部删除”和新增的“编辑提供商”放进顶栏 ⋮；
  - 搜索栏下一行左侧显示“已启用 4 / 7”，右侧是“同步”按钮，同步中按钮内转圈，并显示上次同步时间；
  - 模型目录信息移到列表末尾作脚注。
- D8 模型行第三行依次为类型标签、能力图标组、右对齐的上下文长度（如 128K）。能力用图标组呈现，读屏读出全部能力名称。
- D9 编辑模型页去掉重复的“模型身份”块：身份组只有“显示名称”“模型 ID”两行可编辑字段，规范 ID 与手动修改记录放进脚注。
- D10 上下文、最大输入、输出上限、知识截止日期集中为 2×2 规格区。每格显示简写数值与精确数值，并标出数据来源（目录 / 提供商 / 手动）。点按上下文格弹出带 32K、128K、200K、1M 快捷值的面板。输出上限开放编辑，数据层已有该可编辑字段。
- D11 类型改为单选标签，九项能力改为多选标签；类型切换沿用现有逻辑，自动重置基础能力。会话请求头的三档从底部面板改为页内分段选择。

## 3. 编辑入口与状态

- D3 编辑一律用整页。模型编辑从全高底部面板改为同一屏幕内的整页：沿 X 轴共享切换，返回手势关闭，与宽屏双栏形态一致。删除统一放在编辑页底部的危险行，列表行 ⋮ 菜单保留“删除”作为捷径。字段不超过 2 个的新建（如添加自定义模型）用底部面板，其余新建和全部编辑用整页。模型编辑保持即改即存，页面底部注明“修改即时保存”。
- D14 空态与错误态都给出动作按钮：提供商空态给“添加提供商”；模型空态给“同步”“手动添加”；加载中用骨架行代替单行“加载中”。

## 4. 悬浮菜单

- D12 外观：
  - 同心圆角，外圆角 14dp = 内衬 6dp + 菜单项 8dp；
  - 浅色用最亮的容器色；深色用比 `surfaceContainerHigh` 更亮一档的底色，并加 0.5dp 顶部高光；
  - 两层阴影；
  - 文字 15sp 常规字重；危险项的按压高亮用错误色；
  - 可选分组小标题（`NexaraMenuHeader`）与菜单项右侧的选中勾（`selected` 参数）；
  - 宽度上限 280dp；
  - 定位逻辑 `nexaraMenuPlacement` 不变。
- D13 动效采用方案 B：
  - 入场等一帧，透明度 90ms，缩放 0.92→1 用弹簧（阻尼比 0.8、刚度 700）；
  - 菜单项每项错峰 18ms，最多 6 项；
  - 退场 100ms，淡出并缩到 0.96。

  原型数值计算：达到半透明可见的时刻由现状约 97ms 提前到约 35ms，完全成型约 159ms（现状约 165ms），回弹约 0.12%。入场等一帧还是两帧，以真机 `gfxinfo framestats` 对比结果为准。

## 5. 新增通用部件

| 部件 | 位置 | 用途 |
| --- | --- | --- |
| `NexaraFieldRow` | `ui/common/` | 分组卡片内的无框输入行，含标签、错误、尾部动作，另有密钥变体 |
| `NexaraChoiceChips` | `ui/common/` | 单选或多选标签组，自动换行，选中态带图标着色 |
| `NexaraStatusStrip` | `ui/common/` | 成功、错误、提示、警示四色状态条，替换同步横幅与连接测试文字 |
| `ModelCapabilityBadges` | `ui/common/` | 列表行内的类型标签、能力图标组与上下文长度 |
| `ModelCapabilityIcons` | `ui/settings/` | 九项能力与图标、文案的单一映射，列表与编辑页共用，取代两份重复的能力标签实现 |
| `ModelSpecGrid` | `ui/settings/` | 2×2 规格格子，带数据来源与可编辑格 |

## 6. 展示数据来源

| 展示项 | 来源 |
| --- | --- |
| 启用模型数 / 模型总数 | 由现有 `providerModels` 按提供商分组计数 |
| Tailscale 内网标记 | 由现有 `TailnetEndpoints.isTailnetEndpoint(baseUrl, tailnetState)` 派生 |
| 规格格子的数据来源 | 现有 `ModelInfo.metadataSourceByField` |
| 输出上限可编辑 | 现有 `maxOutputTokens`，已在可编辑字段名单中 |
| 编辑页删除提供商 | 复用现有 `deleteProvider` 与确认对话框 |
| 最近一次连接测试结果与时间 | 新增持久化（现只在表单内存中） |
| 上次同步模型时间 | 新增持久化（现不记录） |

## 7. 风险

- `SettingsPagesBatch1` 中 provider、model 开头的 12 张参考图全部失效；菜单外观改变后，凡截到菜单的截图测试也要更新。由主控收尾时统一重录。
- 悬浮菜单是全站组件（22 个文件、31 处调用）。外观与动效改在组件内部，调用方不用改；宽度上限缩小后，要检查长文案菜单是否截断。
- 模型编辑改为页内整页后，要接上系统返回手势和预测性返回；同步时模型被删除，应自动退出编辑。
- 沿用现有测试标签（如 `providerModelsEditorSheet`），更名的部件保留旧标签。
- 无框输入行要保证 TalkBack 能读出标签、错误和“已保存密钥”状态，最小触控高度 48dp。
- 菜单动效在低端机和省电模式下的掉帧情况，用真机 `gfxinfo` 取证（ColorOS 禁止录屏）。
