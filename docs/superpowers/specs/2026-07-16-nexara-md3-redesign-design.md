# Nexara Material 3 视觉体系重设计

> 日期：2026-07-16
> 分支：`codex/md3-redesign`
> 视觉母版：用户已选择的方案 3
> 状态：设计已获用户确认，待实施计划拆解

## 1. 背景与目标

Nexara 当前使用 Jetpack Compose Material 3 作为底层，但同时混用了自定义玻璃表面、零散描边、硬编码圆角、胶囊控件与卡片套卡片，导致界面既没有形成统一的 Material 3 原生感，也没有建立完整的自有视觉系统。

本次重设计采用“90% 稳定 Material 3 基线 + 10% Nexara 语义特征”的策略：

- 先统一主题、组件、间距、排版、形状和交互状态；
- 再将 Nexara 的差异化集中在思考过程、工具调用、模型状态和会话输入区；
- 保留既有业务功能、导航、数据流和无障碍语义，不以视觉重构为由改变业务行为；
- 让所有页面呈现同一套成熟 Android 原生产品语言，而不是继续逐页局部美化。

## 2. 产品与用户

- **产品表面**：Nexara Android 原生客户端，包括会话、Agent 首页、知识库、Provider/模型、设置、RAG/记忆、备份与工具页面。
- **目标用户**：需要在手机上配置、管理并长期使用多模型 AI 助手的普通用户与高级用户。
- **核心任务**：快速开始或继续会话；理解生成、思考、工具和检索状态；安全配置 Provider、模型、知识库与本地数据。
- **业务语气**：可信、克制、清晰、原生；会话界面保留适度温度，管理界面强调效率与可预测性。

## 3. 视觉主张

Nexara 采用深色、低噪、内容优先的 Material 3 原生视觉。层级主要依靠排版、留白、对齐和 Material tonal surface 建立，分隔线次之，描边与阴影只在确有交互边界时使用。界面不追求夸张的“未来 AI”装饰，而通过稳定的系统组件和少量语义化紫蓝色建立可信感。

会话页是唯一允许出现较强 Nexara 特征的表面：思考过程使用细轨迹和状态节点表达，工具与检索状态沿用相同语义；其他页面优先服从 Material 3 的列表、表单和导航结构。

## 4. 参考系统与技术基线

- **主参考**：Google Material Design 3 / Material 3 Expressive。
- **体验参考**：Solid Explorer 所体现的成熟 Material 原生一致性；只参考平台归属感、信息密度和操作可预测性，不复制其品牌、布局或专有组件。
- **实现基线**：优先升级到官方稳定 Compose BOM `2026.06.00` 与稳定 `androidx.compose.material3:material3 1.4.0`。
- **Expressive 边界**：第一阶段不依赖 `1.5.0-alpha`；只使用稳定组件实现形状、层级、状态和克制动效。未来仅在稳定 API 能明确改善核心流程时增量采用。

## 5. 信息架构与页面节奏

### 5.1 会话页

- 顶部采用标准小型 Top App Bar：返回、会话名、Agent 名、知识库和更多操作。
- 用户消息使用次级容器色气泡；助手正文直接位于背景表面，不额外套卡片。
- 思考完成态采用轻量 tonal strip，并通过细竖线和状态节点连接正文；展开后沿同一轨迹呈现内容。
- 模型与时间作为弱化元数据，不与正文争夺层级。
- 模型、上下文和输入框组成单一底部输入区；不得再使用“大外框套两个胶囊再套输入框”的结构。

### 5.2 Agent 首页与设置

- 首页以清晰的主任务和最近 Agent/会话列表为主，不构造卡片墙。
- 设置采用分组列表、标准 ListItem、Switch、RadioButton、Slider 和 TextField。
- 分组通过标题、间距和必要的 surface container 表达；普通条目不单独成卡。

### 5.3 Provider 与模型管理

- 搜索、同步、添加和批量操作进入 Top App Bar、搜索栏或 overflow；取消四个同权重大按钮矩阵。
- 模型采用可扫描的分组列表或单层容器行，首层展示名称、真实模型 ID、启用状态和主要能力。
- 次要能力、上下文窗口和高级参数通过展开区域或详情页渐进披露。
- 删除、禁用等危险操作使用标准确认对话框与明确错误色，不用整块暗红装饰面板。

### 5.4 知识库、记忆与检索

- 使用列表优先的信息结构，真实区分空态、加载、索引、可用、失败和重试状态。
- 配置项按任务分组，避免把每个参数包成独立卡片。
- RAG、记忆和检索状态沿用会话页的语义色与状态组件，不另建视觉方言。

## 6. 设计令牌

### 6.1 色彩

- 保留现有深色基调与淡紫蓝主色，但全部映射到 Material `ColorScheme` 语义角色。
- 背景使用 `background`；页面主内容使用 `surface`；分组容器只使用 `surfaceContainerLow/Container/High` 层级。
- 主操作和选中态使用 `primary` / `primaryContainer`；普通描边使用 `outlineVariant`。
- 状态色只用于状态本身：成功、警告、错误、信息、索引中；不得作为大面积装饰。
- 删除 `GlassSurface`、`GlassBorder` 等无真实玻璃材质支撑的视觉令牌。

### 6.2 形状

- 统一形状阶梯：`4dp / 8dp / 12dp / 16dp / 24dp`。
- `24dp` 只用于底部输入区、Sheet 等大容器；普通列表和表单使用 `8dp` 或 `12dp`。
- 全圆只用于圆形 IconButton、Switch 轨道、进度环和确属 Chip 的组件。
- 禁止以 `RoundedCornerShape(50)` 作为通用解决方案。

### 6.3 间距与尺寸

- 以 `4dp` 为最小单位、`8dp` 为基础节奏。
- 手机页面水平边距 `16dp`；宽屏内容根据断点提升到 `24dp/32dp` 并限制最大正文宽度。
- 组件内部优先 `8dp/12dp/16dp`；区块之间优先 `24dp/32dp`。
- 所有可操作目标至少 `48dp`，视觉图形可小于触控区域。

### 6.4 排版

- 第一阶段使用真实 Android 系统无衬线字体栈，确保中文、英文和数字一致；删除把系统字体别名伪装为 Manrope/Inter 的命名。
- 正文默认 `15sp–16sp`，行高约为字号的 `1.45–1.6` 倍。
- 标题、正文、辅助信息和标签严格映射到 Material Typography 角色，不在页面内零散复制字号。
- 模型 ID、Token 和代码片段可使用等宽字体，但不得把普通辅助文案全部设为等宽。

## 7. 组件语言

- 优先复用 Material 3 的 `Scaffold`、Top App Bar、Navigation Bar/Rail、ListItem、Card、Button、IconButton、TextField、SearchBar、Chip、Dialog、Sheet、Switch、Slider 和进度组件。
- 自定义组件必须由统一令牌组合，禁止直接读取硬编码颜色、圆角或字号。
- 卡片只用于真正独立、可整体操作的对象；普通列表行不得卡片化。
- Primary Button 每个页面原则上只保留一个主操作；批量和危险操作不得与主操作同权重铺满页面。
- 图标统一使用 Material Symbols/Compose Icons，同一层级保持一致尺寸与线性风格。

## 8. Nexara 专属表达

只保留以下三类自有视觉：

1. **思考轨迹**：细竖线、节点和状态色连接思考、工具、检索与最终回答。
2. **模型状态**：模型选择、上下文占用、生成状态使用紧凑且可访问的统一组件。
3. **会话输入区**：在标准 Material 组件基础上形成稳定的底部组合布局，不扩展为全屏悬浮控制台。

除此之外的按钮、表单、列表、导航和弹窗默认使用 Material 3，不自行发明新形态。

## 9. 动效与反馈

- 使用 Material motion 的容器、淡入淡出、展开/折叠和状态切换节奏。
- 思考轨迹允许轻量状态推进，但禁止装饰性发光、长时间呼吸和无意义循环动画。
- 尊重系统“移除动画/减少动效”设置；关闭后状态变化仍必须清晰可理解。
- 加载、空态、错误和成功均提供可读文案及真实恢复动作。

## 10. 明确禁止

- 玻璃拟态、装饰性模糊、无意义渐变和发光边框；
- 大框套小框、卡片套卡片和每项成卡；
- 胶囊标签堆叠、四个同权重大按钮矩阵；
- 未经令牌管理的圆角、颜色、字号、边框和透明度；
- 以视觉重构顺便改变业务逻辑、导航语义或数据契约；
- 为追求 Expressive 外观直接引入不稳定 Alpha API；
- 截图好看但横屏、大字体、TalkBack、键盘或滚动状态不可用。

## 11. 分阶段实施

1. **设计系统基线**：依赖、ColorScheme、Typography、Shapes、Spacing、Elevation 和共享组件。
2. **会话母版**：按方案 3 完成 Top App Bar、消息、思考轨迹、元数据与输入区。
3. **管理母版**：完成设置首页、Provider 与模型管理，建立列表/表单/危险操作范式。
4. **全站迁移**：Agent、知识库、记忆、检索、RAG、备份和工具页面逐组迁移。
5. **视觉与交互收口**：清理遗留 Glass/硬编码样式，更新截图基线并执行多尺寸、双语和无障碍验收。

每阶段必须形成独立可回滚提交；不得一次性改完全站后再进行视觉验收。

## 12. 测试与验收

- 保持现有业务、导航、状态流和无障碍测试全部通过。
- 为设计令牌、组件契约和关键布局补充静态/单元测试；纯样式代码按项目规则可豁免单测，但必须有截图验证。
- 现有 36 张截图回归逐张更新并人工对照方案 3；不得只批量接受新基线。
- 设备矩阵覆盖 API 31、35、36；覆盖中文、英文、横屏、平板、大字体 2.0x、显示缩放、键盘展开和减少动效。
- 重点验证会话生成/错误/审批/思考展开、Provider 搜索与批量操作、模型卡片/列表、知识库空态与索引状态。
- TalkBack 自动语义测试必须通过；签名候选仍需真机完成完整焦点遍历和听觉检查。
- 视觉验收检查文本裁切、重叠、间距、层级、对比度、触控目标、焦点顺序和返回行为。

## 13. 非目标

- 不在本轮新增浅色主题；
- 不复制 Solid Explorer 的品牌、布局或专有交互；
- 不新增聊天、模型、RAG 或设置业务功能；
- 不以重设计为由重写 ViewModel、Repository 或数据层；
- 不在第一阶段使用 Compose Material 3 `1.5.0-alpha`；
- 不修改已经通过 CI 的 `codex/v0.2-beta` 发行候选分支。

## 14. 完成定义

当所有正式页面使用统一 Material 3 令牌和组件语言、遗留玻璃与无规则视觉被清除、现有功能门禁与设备矩阵通过、视觉对照无显著偏差且真机 TalkBack 验收完成后，才能把本次重设计标记为完成。
