# 体验改进第二批：方案与决定

> 状态：D1–D9 已确认，可实施；P1–P4 方向已确认，交互细节先出原型上真机确认；C1 单独立项。
> 关联：[设置信息架构拆波计划](../plans/2026-10-28-settings-ia-waves.md)、[设置页与会话界面重设计规格](2026-10-17-nexara-settings-chat-redesign.md)、[智能体知识检索工具设计](2026-10-28-agent-knowledge-search-tools.md)。

## 已确认，可实施

### D1 技能：只有全局与工作区两层

技能包的启用、停用、安装、卸载与修改都在全局技能页完成；会话可用的技能等于全局启用的技能，再叠加当前工作区 `.agents/skills/` 下的项目技能。这与桌面端 Agent 开发环境一致：Codex 在用户配置里按技能路径记录全局启停（`[[skills.config]] enabled = false`），并读取仓库 `.agents/skills`；Claude Code 读取用户目录与项目目录的技能。两者都没有会话级的技能名单。

- 不做智能体级、会话级技能名单。智能体编辑页保留“已启用技能”只读摘要，点击跳转全局技能页。
- 智能体的 `skills` 字段（数据库列 `skill_ids`）与会话的 `activeSkillIds` 属于旧版自定义技能，运行时不读取（`SessionToolResolver` 对 `custom` 来源一律不提供）。停止在新建会话时复制该名单，界面不再读写；数据库列保留，不做迁移。与旧版自定义技能函数、遗留字符串的清理合并为一项。
- 取代原型决定 G4 中“技能摘要恢复为逐项开关”的后续项。

### D2 检索引用编号统一

“两者并用”检索方式下，自动注入的资料和 `knowledge_search` 工具结果使用同一套本轮编号。

- 自动注入时，用 `KnowledgeTurnState.citation` 为每条资料分配 K 编号，注入块写成 `[K1 · 文档《名称》]: 正文`、`[K2 · 记忆 · 时间]: 正文`。
- 工具对已注入条目回复“[K1] 已在上方参考资料中”，不再重复正文。
- 检索详情里的编号与模型看到的编号一致。
- 编号只供模型对照。模型回答不要求标注来源，界面不渲染引用角标。
- 测试：注入块与工具结果对同一资料给出相同编号；同一轮多次检索编号不变。

### D3 智能体头像统一

首页列表、新建会话菜单、内屏侧边栏与编辑页使用同一张图标表和同一个底色函数，放在 `ui/common`。现状是编辑页有 10 个预设图标，`agentIconVector` 只映射其中 3 个，其余显示为机器人；首页底色向次要文字色混合 35%，编辑页用原色。

- 底色统一采用一种算法（实施时以编辑页观感为准，首页同步）。
- 单测：编辑页每个预设图标都能映射到对应图标，不落入默认值。
- 真机确认：预设图标、上传图片两种头像在四处显示一致。

### D4 新建智能体弹窗

弹窗字段依次为：名称、类型、模型、系统提示词（可选）。描述移到编辑页。

类型为两段式按钮，下方一行说明。它是一次性模板：创建时写入下表参数，之后都是普通参数，编辑页没有“类型”概念。

| 参数 | 对话型 | 智能体型 |
| --- | --- | --- |
| 新会话默认开启工具 | 否 | 是 |
| 检索方式 | 每轮自动 | 仅工具 |
| 知识库文件访问 | 关闭 | 按需申请 |

- 需为智能体新增“新会话默认开启工具”字段，新建会话时写入会话的 `toolsEnabled`；现有智能体取“是”，保持行为不变。该字段不属于检索参数，建议新增数据库列并补 Room 迁移与迁移测试。
- 编辑页“新会话默认”分组显示并可修改该字段。

### D5 首页入口

- 右上角 + 保持现状：菜单列出智能体，选中即新建会话，末项为“添加智能体”；没有任何智能体时直接弹出创建框。
- 删除列表底部的“添加智能体”行和智能体展开后的“新建会话”行。
- 列表为空时的“添加智能体”按钮保留，它是空状态下唯一的说明与入口。
- 新建会话的动作统一称“新建会话”，右上角无障碍标签同步。

### D6 查询改写默认关闭

- 全局检索参数与智能体独立检索参数的 `enableQueryRewrite` 默认值改为关闭。
- 偏好里未存过该项的用户随新默认值关闭；已手动设置的值保留。
- 开关脚注说明：改写会在自动检索前多一次模型调用，增加首字等待；工具检索不做改写。
- 测试：未存值时读到关闭；已存的开启值保持开启。

### D7 版本号与设置页底部信息

- 版本规则写入 `AGENTS.md` 第 6 节。下一次装机的签名正式版为 `0.3.0-beta`（versionCode 5），对应设置信息架构重组这一功能波次。
- 设置首页底部改为“Nexara 0.3.0-beta（5）· 侧载版 / Play 版”，并去掉“Project Narcis”：
  - 点击这一行复制版本信息：版本名、versionCode、渠道、提交短 SHA。
  - 行尾放 GitHub 标志按钮，打开 `https://github.com/Promenar/Nexara`。
- 提交短 SHA 在构建时写入 `BuildConfig`；源码不在 Git 仓库中时写 `unknown`，构建不得失败。
- GitHub 标志使用官方单色标志的矢量资源，不改形不改色，跟随主题前景色。按钮需要无障碍标签与 48dp 触控区。

### D8 局域网与本机白名单

白名单约束应用自身发起的联网：网页读取 `web_fetch`、媒体下载 `media_fetch`、脚本联网 `exec_js` / `python_sandbox`、MCP 本机地址，以及 Linux 软件源镜像连接。内置命令 `shell_exec`、`python_exec`、`git` 的网络由系统决定，不受白名单约束。

- 白名单保留。在内置模式下它是有效防线；在 Linux 模式下仍约束网页读取与媒体下载。
- 网络访问页的工具表为每行标注适用范围：脚本联网标“仅内置模式”，内置命令标“不受白名单约束”。
- 分组脚注写明：Linux 环境中的命令可直接访问局域网，不受此白名单限制。
- 会话内展示网络可达范围的面板按当前会话的运行模式，灰显不生效的行并写明原因。

### D9 不生效即灰显

原则写入[设置页与会话界面重设计规格](2026-10-17-nexara-settings-chat-redesign.md) §3.5。随后做一次全站排查，列出所有按场景隐藏的设置与操作，逐项改为灰显加原因，并在排查报告中给出清单。已知一例：内置提供商的删除行是直接隐藏的，应改为灰显并说明“内置提供商不可删除”。

## 方向已确认，交互先出原型

### P1 选中文字引用批注

- 范围：助手正文和用户正文；思考过程与工具调用不支持。
- 交互草案：
  - 长按选字后，工具条增加“引用”。
  - 输入区上方出现引用卡，引文最多显示两行，下面是这段引文的批注输入框。
  - 可以连续添加多张引用卡，每张可单独删除。
  - 主输入框仍可写整体说明。
- 发送：消息结构化保存引用列表，每项包含来源消息 ID、引文和批注。发给模型时，每项序列化为“引文块 + 批注”。用户气泡显示引用卡，点击引文定位到来源消息。
- 需要数据模型与持久化变更：消息新增引用字段，备份、导出与分支复制都要带上。
- 待原型确认：
  - 批注框是否必填；
  - 只有引用卡、主输入框为空时能否发送；
  - 引用卡在输入区的最大高度与折叠方式。
- 技术核实：项目 Compose BOM 为 2026.06，实施前核实自定义文本菜单项接口。真机验证 ColorOS 工具条，以及跨 Markdown 段落、代码块、表格的选择表现。

### P2 思考阶段的动效

思考按流式处理，不用平淡的等待效果。

- 现状：
  - 浮岛动效的流式阶段已经随出字速率变化：`OutputRateMeter` 以每秒 60 字为满档，影响闪烁密度与 0.7–1.0 的亮度。
  - 但速率只统计正文（`ChatScreen.kt` 传入 `streamingContent.length`）。
  - 思考阶段映射为等待（`generationMotionPhase` 把 `THINKING` 归入 `WAIT`）；首包后若只有思考内容，也按等待显示。
- 改法：
  - 速率表统计正文加思考内容的到达字数。
  - 有思考内容到达即进入流式家族；只有在没有数据到达时，才显示等待。
  - 思考可用与正文不同的配色，两者不必分出谁更显眼。
- 速率联动扩展到各动效样式：节奏与幅度都随速率变化，速率为零时平滑回落到等待。
- 不输出思考内容的模型无法区分思考与等待，只能显示等待。
- 动效预览页的演示序列补上思考段。

### P3 折叠思考块的滚动预览

- 现状（`PipelineBubble.kt` 的 `ThinkingTrace`）：
  - 折叠时单行显示思考内容末尾 180 字。
  - 每次内容更新都用 `scrollTo` 直接跳到末尾。
  - 截取窗口本身随新内容整体左移。
  - 结果是文字成块跳动，没有连续运动感，显得比实际慢。
- 方案方向：
  - 匀速传送：维护显示位置，以与到达速率匹配的速度平滑滚动追赶末尾，复用重设计规格 §5.7 流式匀速放出的追赶算法。积压越多滚动越快，停止输入后平滑停住。
  - 稳定缓冲：保留更长的文本缓冲，按整段裁剪，避免每次更新都整行重排。
  - 新到字符渐显，左侧已有渐隐遮罩保留。
  - “思考中 N 秒”标题加一道微光扫过，扫过节奏随速率变化。
  - 备选：两行纵向滚动，新行从下方滑入。原型中与单行方案对比后选定。
- 系统关闭动画时退化为直接显示末尾文字。

### P4 长工具链中的进展语

- 现状：工具使用提示词没有要求模型说明进展。工具轮之间若有正文，会作为正文段显示在工具组之间（`PipelineStep.Content`），界面已支持。
- 两层机制：
  - 提示词：开始一组工具调用前、或换一个方向时，先用一句话告诉用户正在做什么；不复述工具结果，不写空话。
  - 运行时提醒：连续若干轮工具调用、或距上一句面向用户的文字超过一段时间，仍没有新的面向用户的文字时，在下一次请求末尾追加一条系统提醒，要求先用一句话说明进展再继续。
    - 提醒只进协议历史，不显示在会话里。
    - 追加在末尾，不改动已缓存的前缀。
- 默认阈值建议为 4 轮或 60 秒，在原型阶段按真机体验调整。
- 待确认：进展语用正文样式，还是比正文更轻的次要样式。

## 单独立项

### C1 输入缓存命中

初步判断（尚未用服务商返回的缓存数据核实）：检索资料、知识库目录、技能清单和当前时间都写在系统提示里；技能清单随本条消息中的 `$名字` 变化，系统提示又排在全部历史之前。其中任一项每轮变化，整段前缀缓存都会失效。方向是让系统提示保持稳定，把每轮变化的内容移到最后一条用户消息。立项时先用真实用量数据确认现状。
