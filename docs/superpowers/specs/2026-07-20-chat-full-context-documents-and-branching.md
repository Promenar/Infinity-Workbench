# Nexara 会话完整文档上下文与消息分支规格

> 日期：2026-07-20
> 状态：用户已确认，进入实施

## 1. 产品语义

- 输入栏上传 `.txt` 或 `.md` 表示用户要求模型完整阅读该文件。客户端必须把完整文本作为当前用户消息的上下文附件发送，不得分块检索、摘要或静默截断。
- 纯文本模型与多模态模型使用同一附件语义和同一文本内容；Provider 原生文件接口不作为首轮正确性依赖。
- 只有知识库文档走向量、关键词或混合检索。希望长期按需引用的资料应引导用户添加到知识库。
- 文档或完整请求超出当前模型上下文预算时，必须在网络请求前阻止，并明确提示切换长上下文模型、压缩既有会话、另开空白会话或添加到知识库。
- Nexara 不新增专门的历史会话导入协议。现有会话导出为 Markdown/TXT 后，可重新作为完整文档附件上传。
- 每条已持久化消息提供“从此处分支”操作。分支创建新会话并复制截至指定消息的稳定历史快照。

## 2. 文档附件契约

每个文本文档附件至少保存：稳定 ID、原始文件名、MIME、UTF-8 文本、原始字节数和 SHA-256。发送时读取为不可变快照并随用户消息持久化；重试、重新生成、后台恢复、导出和分支复制都使用该快照，不再次依赖 `content://` URI。

协议内容使用文档 SHA-256 绑定的确定性边界，避免正文伪造固定关闭标签：

```text
 [NEXARA_DOCUMENT name="..." type="text/markdown" sha256="..."]
<<<NEXARA_DOCUMENT_BEGIN sha256>>>
完整内容
<<<NEXARA_DOCUMENT_END sha256>>>
```

文件名和属性必须转义；附件内容按不可信用户资料处理，不能进入系统提示词。附件边界只负责区分资料与用户指令，不改变原文。

## 3. 上下文预算

- 预算输入覆盖最终系统提示词、活动消息、文档附件、工具定义、RAG 注入内容和输出预留。
- 首轮使用可解释、偏保守的 UTF-8 字节上界估算；模型有明确 `contextLength` 时以该值为硬上限，未知或零值不得伪造容量。
- 输出预留取会话/Agent 的 `maxTokens`，并保留固定协议开销。
- 文件读取阶段只做格式、编码、大小与二进制校验，不用尚未路由的会话别名做容量硬拒绝。唯一容量硬门禁在模型路由和最终 Prompt 构造后、Provider 网络请求前执行，确保用户覆盖使用稳定模型 ID、目录容量使用实际远端 ID，且后台恢复和 RAG 变化不能绕过。
- 任何超限路径均不得发起 Provider 请求；不得自动降级为 RAG、摘要或截断。

## 4. 分支不变量

- 新会话继承：Agent、模型、系统/自定义提示词、推理参数、RAG 选项、工具开关、激活 Skill/MCP 配置，以及截至分支点的稳定消息内容和附件快照。
- 新会话重置：ID、标题、创建/更新时间、草稿、未读、置顶、滚动位置、循环状态、待干预、审批请求、活动任务、统计、活动任务树和所有生成运行态。
- 只复制截至指定消息的历史；新消息 ID 全部重建并重映射 `parentMessageId`。工具调用 ID 在单个分支快照内成组保留，避免拆散 `toolCalls` 与 `toolCallId` 的对应关系。
- 不复制失败中的空助手占位、待审批工具执行和未完成工具链；分支点若落在不完整工具回合，必须拒绝并提示选择稳定消息。
- 不复制旧摘要：摘要可能包含分支点之后的信息。首轮分支会话摘要为空，需要时重新生成。
- 不复用原会话工作区根或物理路径。新会话创建独立空工作区，避免两个分支互相修改文件；工作区内容复制列为后续显式能力。

## 5. 导出

- Markdown/TXT 导出包含会话标题、创建时间、默认模型、每条消息角色与时间、AI 实际模型，以及文本文档附件的文件名、MIME 和完整内容。
- 导出不承诺恢复数据库实体、运行态、工具审批或工作区；它是人类可读且可作为完整上下文重新上传的稳定文本。

## 6. 非目标

- PDF、DOCX、网页、音频和视频附件。
- Provider 专有文件上传、文件缓存或 Files API。
- 文档自动摘要、自动 RAG 降级或静默裁剪。
- 恢复旧会话实体、ID、运行态或原工作区。
- 分支时复制工作区文件、知识库索引、向量或知识图谱派生物。

## 7. 完成定义

- TXT/MD 可从输入栏选择、预览、移除并发送；无正文时也可仅发送附件。
- 完整内容进入每一种聊天 Provider 的同一协议文本，重启、重试、重新生成和后台生成保持一致。
- 已知容量模型超限时在 Provider 请求前被阻止，并有明确中文/英文恢复建议。
- Markdown/TXT 导出可重新上传并完整保留会话文本与附件。
- 稳定消息可分支成独立会话，运行态、摘要和工作区不串线。
- 定点 JVM、全量 JVM、Lint、截图、AndroidTest 编译、API 31/35/36 相关流程和人工 actual 视觉验收通过。
