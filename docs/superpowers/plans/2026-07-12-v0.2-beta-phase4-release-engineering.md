# Nexara v0.2-beta Phase 4 Release Engineering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可重复的测试、签名、冷安装与 GitHub Release 流程，产出可校验的 `v0.2-beta` 侧载 APK。

**Architecture:** PR CI 不接触签名秘密，只运行全部质量门禁；tag workflow 在受保护 environment 中临时恢复 keystore，验证 tag/version、构建签名 APK、实机冷装、生成 SHA-256 并创建 Release。

**Tech Stack:** Gradle、Android Lint、GMD、Compose screenshot、apksigner、GitHub Actions、GitHub CLI/Release API。

## Global Constraints

- 普通 PR/push 绝不加载 release keystore 或密码。
- 真实 LLM 集成测试默认不在 PR CI 运行；手动 workflow 只能从受保护 environment 注入测试环境变量，日志禁止显示地址、Authorization、Prompt 与响应正文。
- 签名配置只读取 `NEXARA_KEYSTORE_PATH`、`NEXARA_STORE_PASSWORD`、`NEXARA_KEY_ALIAS`、`NEXARA_KEY_PASSWORD`。
- tag 必须严格等于 `v${versionName}`。
- Release APK 必须通过签名验证、API 35 冷安装/冷启动/主流程 smoke 和 SHA-256 校验。
- 发行说明明确：不兼容旧数据、GGUF 非稳定能力、后台任务不支持重启续传。
