# Nexara v0.2-beta Phase 1 Security and Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可发行的密钥、日志、网络、Room 和备份安全基线，使所有敏感配置加密存储且备份可验证、可回滚。

**Architecture:** `SecretStore` 统一保存全部 Key，业务列表只暴露是否已配置；Room 改为新文件 schema v1；备份先编码/加密/校验，再一次性事务恢复；WebDAV 全程原始字节并使用临时上传与 MOVE。

**Tech Stack:** Android Keystore AES-256-GCM、PBKDF2-HMAC-SHA256、Room/KSP、Ktor MockEngine、kotlinx.serialization、ZIP、Robolectric、Compose UI Test。

## Global Constraints

- 数据库文件固定为 `nexara_v2.db`，schema version `1`，`exportSchema = true`，禁止 `fallbackToDestructiveMigration()`。
- Keystore alias 固定为 `nexara.secrets.v1`，算法 `AES/GCM/NoPadding`，256 bit Key，12-byte 随机 IV。
- 可选密钥备份使用 16-byte salt、PBKDF2 600,000 次、AES-256-GCM、12-byte IV。
- Provider API Key、Vertex JSON、Tavily、Embedding、WebDAV 密码和自动备份密码全部进入 `SecretCatalog`。
- Release 不记录 Prompt、响应、Authorization、Cookie、SQL 参数、完整堆栈或用户文件内容。
- `allowBackup = false`、`usesCleartextTraffic = false`；Provider 与 WebDAV 保存前都做 HTTPS 校验。
