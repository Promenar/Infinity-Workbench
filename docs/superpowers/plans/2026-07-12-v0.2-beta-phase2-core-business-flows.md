# Nexara v0.2-beta Phase 2 Core Business Flows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Provider、工具审批、Session 工作区、文件索引、RAG/KG 和分享导入形成真实、隔离、幂等的端到端业务闭环。

**Architecture:** 每次模型请求按稳定复合模型 ID 解析 Provider；工具以持久化 ledger 原子 claim；工作区所有操作携带 `workspaceRootUuid`；文件变更发布统一索引事件并以候选索引事务替换；分享和 SAF 复用同一导入器。

**Tech Stack:** Kotlin Coroutines/Flow、Room transaction、Ktor、Jetpack Compose、Storage Access Framework、Robolectric、Compose instrumentation。

## Global Constraints

- 模型持久化键固定为 `providerId::remoteModelId`，真实 API 参数仍使用 `remoteModelId`。
- 每次请求在建连前完成 `modelId -> providerId -> config -> protocol/client` 解析。
- 工具唯一键为 `sessionId + assistantMessageId + toolCallId`，副作用最多执行一次。
- 文件 UUID、父节点、规范化路径和软链接均必须受当前 `workspaceRootUuid` 约束。
- 重索引失败不得破坏旧可用索引；删除必须清理所有派生记录。
- 所有成功导入必须给出逐项结果并发布索引事件；禁止 Toast 假成功。
