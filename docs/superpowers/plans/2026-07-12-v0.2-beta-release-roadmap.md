# Nexara v0.2-beta Release Roadmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Nexara 从可演示工程收敛为通过安全、数据、业务、后台生成、UI 和发布门禁的 `v0.2-beta` GitHub 侧载 APK。

**Architecture:** 采用四阶段垂直门禁，先冻结安全与数据契约，再闭合业务数据流，然后重构生成生命周期与发行 UI，最后建立 CI、签名和 GitHub Release。冲突热点按阶段串行集成，每项业务改动均先写失败测试，再以最小实现转绿。

**Tech Stack:** Kotlin 2.2、Jetpack Compose Material 3、Room、Ktor、Android Keystore、Foreground Service、JUnit/Robolectric、Compose UI Test、Gradle Managed Devices、GitHub Actions。

## Global Constraints

- `minSdk = 31`，`compileSdk = 36`，`targetSdk = 36`。
- 目标版本为 `versionCode = 2`、`versionName = "0.2-beta"`、Git tag `v0.2-beta`。
- 不兼容 `v0.1-beta` 数据；数据库使用 `nexara_v2.db`、schema v1 新基线。
- 发行只承诺深色主题、简体中文与英文。
- GGUF 不进入稳定能力，发行 UI 隐藏本地模型入口。
- 后台生成只延续用户在前台发起的单个任务，不支持设备重启续传或多会话并发。
- 所有云 Provider 与 WebDAV 仅允许 HTTPS。
- Key 默认显示 `****`；只有用户主动点击眼睛时临时显示，离页后重新隐藏。
- 备份默认不含 Key；勾选完整 Key 时必须设置备份密码。
- 未通过单测、Lint、Compose E2E、截图回归、三类设备走查、签名校验和冷安装，不得创建 Release。

## 主控所有权

- `NexaraApplication.kt`、`ChatViewModel.kt`、`NexaraDatabase.kt`、`MainActivity.kt`、`NavGraph.kt`、`AndroidManifest.xml`、`app/build.gradle.kts` 在任一时刻只能有一个写入者。
- `ProviderManager.kt` 与 Provider 安全/路由任务必须由同一阶段负责人串行提交。
- `WorkspaceRepository.kt`、`FileOperationRepository.kt` 与索引事件契约必须在同一批次集成。
- `ChatScreen.kt`、`NexaraPageLayout.kt`、两份 `strings.xml` 由 UI 阶段统一收口。
- 实现 Agent 不读取 `.env`、keystore、测试私钥或本机凭证；所有测试使用假值和 fixture。
- 真实聚合 LLM 仅由主控在显式 integration profile 中通过进程环境变量注入；默认单测、PR CI、截图测试和 Release APK 均不得依赖或包含该地址、Key 与响应正文。
